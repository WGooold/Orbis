# ADR-0084：Host 归一化消息内容与 App 占位渲染

日期：2026-11-19

Status: accepted（决策已确认；实现、自动验证、部署和用户验收分别记录）

Feature：MSG-RENDER-01。

关联：[ADR-0032](0032-host-owned-agent-state-model.md) §5、[ADR-0051](0051-ui-style-motion-and-visual-stability-freeze.md)、[ADR-0058](0058-shared-interaction-motion.md)、[ADR-0064](0064-protocol-compatibility.md)、[ADR-0066](0066-unified-chat-card-presentation.md)、[ADR-0080](0080-mobile-math-rendering.md)。

## Context

Codex 等后端会在 Markdown 正文中输出 `:codex-file-citation{...}` 一类指令。Host 当前主要把它们作为文本消息转发；Android 和 iOS 各自解析 Markdown 与文件链接，不能稳定地把同一内容还原成一致的原生组件。未来来源也可能增加 App 尚未实现的展示类型。直接丢弃未识别内容会造成信息缺失；把未知原生载荷直接交给 App 或把指令源码显示给用户，会暴露后端格式并导致跨端表现不一致。

ADR-0032 的 `DisplayEntry.kind = undisplayable` 表示历史条目没有可显示消息，App 会略过该条目。它适用于内部事件和确实没有正文的条目，不能表达“消息中有用户可见内容，但当前 App 没有对应渲染器”。现有 `RemoteContent` 也只涵盖文本、思考、产物和工具调用，不能独立表达带原位置的原生内容。

本决策定义 Host、协议与各 App 的共同职责：Host 识别并归一化来源特有的内容，App 渲染自己支持的种类；当前 App 或旧客户端不能原生渲染时，仍在原消息位置给出安全、可读的占位表示。

## Decision

### 1. 原文是权威记录，展示结果由 Host 归一化

Host 的后端适配层解析来源特有的消息指令，并生成与来源消息和文本范围关联的版本化展示投影。Android、iOS 及后续 App 消费相同的投影，不自行解析 Codex、Claude、Pi 等来源的私有语法，也不根据展示文本反推文件身份或原生事件。

Canonical 消息、来源身份、时间顺序和历史同步仍为权威数据。展示投影是可重建的派生表示，不替换、删改或回写 canonical 正文。投影应保留稳定条目身份和原位置；来源消息更新、流式完成、历史重放及重连使用同一解析规则。

### 2. 使用类型化、最小化的展示数据

每个已识别的丰富内容项使用明确的 `renderKind` 和该种类所需的最小字段，并携带安全的 fallback 描述。投影只包含绘制、辅助功能、复制和受控打开所需的数据；不传递任意原生对象、工具私有字段、脚本或可执行 HTML。来源解析失败时，不猜测类型。

首批包括普通 Markdown 与已支持的数学公式，以及 Codex 文件引用。文件引用至少保留显示文件名、`source` / `output` 用途、可选行号和 Host 侧引用身份；完整路径不作为默认可见文案。`output` 文件可在回复末尾归并为一个产物卡片；`source` 保留在正文原位置作为引用。两处都出现同一文件时，正文引用与末尾卡片对应同一身份，避免重复产物卡片。

### 3. App 支持的种类原生渲染，其余就地显示占位符

每个 App 使用现有组件渲染已实现的 `renderKind`，使用 Host 提供的文件名、行号、标题及动作语义；平台布局和动效沿用 ADR-0051 / ADR-0058。无需为了视觉一致而强求所有 App 采用相同的原生控件。

对于 Host 已识别、但该 App 暂无原生渲染器的用户可见内容，App 必须在原来的段落位置渲染低干扰占位符，不得静默丢弃，也不得展示原始指令、内部 JSON 或未知载荷。占位符只显示通用、简短的可访问标签；不支持点击动作时不伪造可交互状态。正文项按原位置以内联标签呈现，独立块以紧凑占位块呈现。

这项占位规则不改变 ADR-0032 对纯内部原生事件的处理：无用户可见内容、无可恢复正文的事件继续标记为 `undisplayable` 并隐藏；未知原生事件也不根据事件名或载荷臆造面向用户的内容。

### 4. 文件引用通过现有 Host 文件能力操作

引用点击只携带 Host 已解析的引用身份和可选行范围，沿用既有文件校验、范围下载及 App 下载状态。Host 按原会话工作目录解析相对路径，并在操作时确认目标文件可用；不得把来源路径当作可任意打开的 URL 或本机文件 URI。App 支持的文件类型可在用户点击后打开预览；暂不支持预览的类型显示文件占位卡片并提供既有下载入口。

文件引用本身不代表文件已上传、文件内容已随消息发送或 Host 已成功读取文件。不可用、路径越界或文件身份变化时使用现有错误反馈，不展示过期内容。

### 5. 流式解析与复制保持稳定

解析器只在 Markdown 语法上下文中识别指令；代码围栏、行内代码、转义定界符、链接地址及原始 HTML 中的相同字符保持原文语义。未完成的流式指令暂缓显示该指令候选范围；完整识别后一次替换为组件，语法无效时恢复完整原文，不吞掉后续正文。

普通文本持续流式显示。异步解析结果按消息身份与正文版本核对，迟到结果不得覆盖较新的正文或展示投影。复制与文本选择应得到用户看到的可读标签和正文，不复制私有控制语法；文件路径仅通过显式复制路径操作提供。

### 6. 新展示能力按能力兼容投影

新增展示字段和类型遵循 ADR-0064。Host 仅对确认支持相应展示协议的 App 发送富展示投影；旧 App 或能力未知的客户端收到兼容的普通文本投影，其中已识别的私有指令用安全 fallback 文案替换。未协商时不发送旧端可能因严格 schema 拒收的新枚举或字段。展示语义变化提升投影版本，客户端按既有版本规则重建展示缓存；不提高业务协议版本号来代替能力协商。

## 覆盖范围

| 场景 ID | 目标行为 |
| --- | --- |
| MSG-RENDER-01-SOURCE | 各来源的正文指令由 Host 统一识别；App 不自行解析私有语法。 |
| MSG-RENDER-01-NATIVE | Android、iOS 和后续 App 对已支持的展示种类使用各自原生组件。 |
| MSG-RENDER-01-FALLBACK | 已识别、用户可见但 App 不支持的正文项在原位置显示通用占位符；不显示原始私有载荷。 |
| MSG-RENDER-01-HIDDEN | 不含用户正文的内部 / 未知原生事件沿用 `undisplayable`，不制造噪声占位符。 |
| MSG-RENDER-01-CITATION | `source` 文件引用内联显示；`output` 引用可归并为回复产物卡片；来源行号和文件动作与 Host 引用身份关联。 |
| MSG-RENDER-01-STREAM | 部分指令、完成、无效语法、重复通知、历史重放和重连不会闪现源码、丢正文或倒退到旧投影。 |
| MSG-RENDER-01-COPY | 选择与复制包含可读展示文本，不泄漏私有指令；复制路径是显式动作。 |
| MSG-RENDER-01-COMPAT | 新 App 获取富投影；旧 App / 未确认能力收到纯文本兼容投影，严格 schema 不因未知字段或类型拒收消息。 |

## 安全与内容边界

消息与文件元数据均按不可信输入处理。解析仅识别固定语法与类型，不执行消息内容、不渲染任意 HTML、不自动读取引用文件正文、不访问外链。占位符不得回显未知原生对象或完整敏感路径。文件打开和下载复用现有 Host 归属、路径规范化、文件身份校验与传输边界。

Malformed 指令若无法安全确认类型，保持为普通文本；合法但不支持的展示类型才进入占位符。拒绝、截断或不可用的内容必须保持明确状态，不能伪装成完整展示。

## 实现与验证

本 ADR 记录产品与协议决策，不表示代码、部署或用户验收已完成。实现需更新 Host 的实时与历史消息适配、版本化展示投影、Android / iOS 消费层及旧客户端兼容路径；已有 Markdown、数学公式、产物卡片、文件下载能力优先复用。协议变更依照 ADR-0064 验证最近已发布 Host、Relay、Android 与 iOS 的新旧组合。

回归应使用同一份跨平台消息夹具覆盖正文位置、代码上下文、行号、输出卡片去重、未知 renderKind 占位、未完成 / 无效指令、复制、文件不可用、历史回放和旧端兼容。自动验证、候选安装包、独立环境、用户手动验证与验收结论分别留证；未验证的 App / 协议组合不标记为兼容。
