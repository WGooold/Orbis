## Context

用户在 r14 基线上反馈了 7 项问题与需求。本次先登记决策、回归方案和 ticket，暂不改代码。下列现状是基于 `main` `d4e7305` 读源码得出的判断；尚未在设备上复现，实施时须先复现再修复。

1. **打字机效果不按顺序。** 两端每收到一批流式增量，就从“当前时刻”开始给这一批排 30ms 错开，不会接在上一批尚未显示的尾部之后。上一批的尾部和下一批的开头因此同时渐显；一批超过 15 个字素后，后面的字素在 450ms 处一起出现（iOS `RevealClock`，`ChatView.swift:842`；Android `GlyphRevealClock.observe`，`StreamingText.kt:40`）。Android 还给每个 Markdown 段落单独建时钟（`StreamingText.kt:72`），新段落挂载时整段作为基线直接显示，前一段仍在渐显时后一段已经出现。
2. **跟随视角时闪屏。** 用户推测，执行到一半的工具先以另一种形态渲染，再变回工具卡片，因而造成闪屏。源码中存在符合该推测的路径：Android 把尚未归入消息的运行中工具放在列表末尾，渲染为 `ToolCard`，正文最多 2000 字符等宽原文，会随输出增高；归入消息或完成后，该行被移除，工具改以消息内 56dp 紧凑卡片出现（`MainActivity.kt:2158`、`MessagePresentation.kt:185`）。工具块的 key 还会在取得 `toolCallId` 后从位置 key 变为 id，摘要到达时又从 `CompactDisclosure` 换成 `ToolSummaryDisclosure`。也可能另有原因，例如消息身份替换、跟随滚动实现、字形裁切使用过期布局。必须用真实输出确认。
3. **Android 首页视口被挤走。** 首页会话按会话 `modifiedAt` 倒序排列（`HomePresentation.kt:75`）。`LazyColumn` 默认以首个可见项的 key 保持位置：新会话插到顶部时，视口仍跟着旧首卡，新卡落在视口上方；首卡被重新排序到别处时，视口也跟着它跳过去。这与聊天记录此前修复的锚点问题类似。
4. **设置页结构。** 旧设置页及连接优先级的 UI 和逻辑已在 `0ab4bc3` / r13 删除（[ADR-0050](0050-fixed-lan-relay-routing.md)）。当前首页右上角是“下载 + 更多操作”菜单，菜单含连接状态、添加电脑、取消配对；添加 / 取消配对还分散在首页电脑切换菜单、iOS 目录底部的单独省略号菜单等多处。连接状态页和首页下载页在 iOS 没有右滑返回：隐藏导航栏后，系统手势失效。Android 上这两页整页替换首页，既没有入场动画，也没有右滑返回。
5. **Android 首页没有下拉刷新。** iOS 首页已经使用 `.refreshable { store.refresh() }`。
6. **聊天中点击下载缺少去向反馈。** 下载任务只出现在下载页和下载按钮的角标上。
7. **回归要求。** 上述全部写入冻结基线；每次 UI 功能或设计改动都必须在模拟器上完成手动和自动回归；新的 UI 设计也必须同时写好对应的回归测试。

## Decision

新增与修订的稳定 ID 在 ADR-0051 r15 登记：M04 修订；新增 S22、M14、M15、M16、V20、V21；S18、S19 补充 r15 修订。实施并验收前，现有行为仍按原规则保持。不能把这些条目写成已交付。

### 1. 流式逐字揭示按顺序推进（M04 修订，UI-01）

- 每条流式消息只有一个揭示游标，覆盖该消息的全部正文、标题、列表、引用和代码块。字素按渲染顺序开始渐显，开始时间单调不减。任一时刻处于渐显中的字素必须是游标前的连续区间，不能出现前后两处同时渐显。
- 新批次排在尚未揭示的尾部之后。基础间隔 30ms，单字渐显 120ms，模糊 6pt/dp。积压的揭示时长超过 450ms 时，压缩后续间隔，使全部积压在 450ms 内开始揭示；间隔小于一帧时，同一帧依次开始多个相邻字素，但不跳序、不并行开第二段。
- 只有消息首次挂载、或流式状态刚开启时，已有文字作为基线直接显示。之后流式过程中新出现的段落、列表项和代码块继续使用同一游标。Android 必须把段落级时钟提升到消息级，并为各块计算基准偏移；iOS 沿用消息级 `base` 偏移。
- 正文不是前缀续写（被重写、截短）时，已显示的内容立即落定，不重放。消息结束时，剩余积压按压缩节奏在 450ms 内揭示完，不瞬间跳出。Android 同时活动的字素仍不超过 128 个。iOS 17 和减少 / 关闭动画路径保持直接显示。布局、选择、链接和辅助功能语义不变。

### 2. 运行中工具呈现连续，跟随时不闪屏（V20，UI-02）

- 先定位，再修。必须用隔离 Host 上的真实 Pi / Codex / Claude 输出复现。可以录制事件流后在夹具中回放，但不能使用用户正在使用的 Host。逐帧录屏并记录每帧的投影行 key、行高、首个可见项、偏移和跟随状态，与 Host 事件时间线对齐，确认闪屏帧对应哪次变化。如果不是工具形态切换，按实际原因修复，并在 ticket 中记录被排除的假设和证据。
- 目标规则：工具从首次出现到完成保持同一呈现身份。消息内与消息外使用同一 `toolCallId` 身份和同一紧凑卡片形态，运行中不显示会随输出无限增高的原文块。归入消息、取得 id、结果或摘要到达时，只更新卡片内的状态与摘要，不移除行再重新插入。
- 跟随模式下，这些变化不能造成视口上跳 / 回跳、空白帧、整屏重绘闪烁，也不能触发跟随状态切换。非跟随时遵守 V02 / V03，阅读锚点不动。
- **定位结论（2026-10-30，Android，隔离 Host 上的真实 Pi 输出）**：在三次逐帧捕获中，闪屏都发生在第二个工具结束时。工具结果条目先于调用它的助手条目到达，新叶子的父节点暂缺，投影只能得到这一个条目，聊天约 3 帧只剩它一行，随后父条目到达又恢复全部内容。根因是条目乱序到达时发布了被截断的投影，与工具卡片的形态无关。这几次 Pi 运行中，运行中的工具都挂在助手轮次内（`tool-live` 消息），没有出现列表末尾的独立工具卡。工具结束、正文规范化时，轮次行的 key 会变化并重建，高度变化约 11px；聊天行没有进出场动画，所以不是闪屏。修复：在条目链因缺父而断开时保留当前已显示的行，直到链重新接上（`SessionGraph.isWaitingForParent`，覆盖检查点 / 补丁、实时增量和缓存种子三条投影路径）；修复后用真实输出复测，会话条目数不再回落。iOS、Codex 与 Claude 后端尚未用同样方法验证；用户消息与轮次行在规范化时更换 key 的问题另行跟踪。

#### 2026-11-01 Android 连续更新与实时消息交接补充

独立修复决策、状态边界与验证限制见 [ADR-0057](0057-android-tool-transcript-continuity.md)。

- 隔离 Host 的真实 Pi 六次工具调用再次触发回落：转录数先从 11 降至 9、再从 13 降至 11，各约两帧后恢复。此前保护只保留已落盘行，仍提前移除了尚未完成交接的实时正文 / 工具行。可控设备回放还证实：第一份缺父结果推进 `sourceHeadLeafId` 后，第二次同 head 更新或其后继条目会绕过保护，列表从 17 行缩为 1 行，顶部仍显示更早消息入口。
- Android 单独保存被保留画面的叶子 `retainedProjectionLeafId`，重复 patch、恢复 checkpoint 和缓存首屏都相对这个显示锚点检查连续性，不能用已推进的源端 head 证明画面已经完成交接。缺父期间保留已显示的 canonical 与 live 行；完整 live 库存继续更新工具与轮次事实，尚未有 canonical 替代的实时行暂留。补历史或缓存即使已补齐父节点，也不能单独发布新 canonical 行并保留旧 live 副本；它们缺少实时库存，继续显示保留分支，直到完整 source checkpoint 一次交接。确证的回退 / 分支切换、来源未知和缓存重建清除暂留状态。同步未完成时不发送已应用状态确认，仍沿用既有恢复请求。
- 本次恢复 V20、V09、V01–V04、V18 的既有行为，不调整双端共享协议、视觉或滚动参数。新增 `SessionToolContinuityTest`、`ToolContinuityInstrumentedTest`；真实捕获补充源序号、head、父链与分页边界。自动、设备与手动结果统一记录于 `.artifacts/ui-regression/20261101-pi-tool-continuity/summary.md`；未完成项不能计为验收通过。
- 最终专项结果：564 项 Android 单元、Debug / AndroidTest 构建与 A1–A4 各 11 项设备回归通过；真实 Pi 六次工具调用捕获 7,105 帧，无消息数回落并正常结束。全量原始 142 项中 12 失败 / 7 跳过，ChatEntry 冷启动性能按方案单次复测通过后，剩余 11 项失败与本轮同设备基线一致。完整 C01–C18、全量 L4、iOS / Claude / Codex 新一轮真实输出未完成，不签署整体 UI 门禁通过。

### 3. 首页列表视口稳定（V21，UI-03）

- 会话新增、关闭、排序变化、状态或标题刷新，以及完整快照替换，都不能把用户视口挤走。范围覆盖 iOS / Android 首页及目录抽屉列表；当前问题已在 Android 首页确认，其余位置需逐一核验。
- 用户停在顶部时（首项顶边距视口顶部不超过 8pt/dp），变化后保持在顶部，新的首卡可见。已向下滚动时，保持视口内第一张完整可见卡片的屏幕位置；如果这张卡片本身被移到别处，则保持原像素偏移，不跟随它跳走。
- 拖动和惯性期间不重新定位；变化在手势结束后结算。卡片换位使用现有放置动画，不能整页跳动。视口位置只因用户滚动或显式操作改变。

### 4. 设置页与配对入口（S22，修订 S18 / S19，UI-04）

- 旧设置页与连接优先级已按 ADR-0050 删除，不得恢复；本次只核对没有残留的入口、文案、状态、测试或深链。
- 现有连接状态页改为“设置”页。分区自上而下：Agent 供应商（S19 的卡片、配额币和切换保持不变）→ 当前连接（连接状态、方式、延迟、加密；Android 的连接诊断提示卡位于此区上方）→ 配对信息（只读）。S23 / UI-07：延迟行始终显示 Host 最近公告的当前生效路径 RTT，四舍五入为整数毫秒；没有样本或未连接时显示“暂不可用”，不触发布局增删或选路变化。删除 iOS 现有的“已配对电脑”切换区，两端都不在设置页切换电脑；切换电脑只在首页电脑行和侧边栏底部电脑菜单中进行。顶栏保留重新连接图标。
- 首页右上角只有两个图标按钮：下载、设置（齿轮）。删除“更多操作”菜单。点齿轮直接进入设置页。
- 连接胶囊保留，继续按 S18 显示连接方式、加密以及“正在同步 / 同步失败”；失败时，胶囊旁的重试按钮仍然保留。但胶囊不再响应点击、不再进入设置页。它的辅助功能语义从按钮改为状态文本。
- 目录筛选菜单中的入口，以及 provider 不匹配对话框中的入口保留，文字改为“设置”，点击后进入设置页。这两处是排障路径，不算右上角的入口。
- 添加电脑与取消配对只保留一个入口：点击侧边栏底部的电脑行，在弹出的菜单中切换电脑、添加电脑或取消配对当前电脑。iOS 目录底部单独的省略号菜单并入这一菜单；首页电脑切换菜单删除“添加电脑”；其他添加 / 取消配对入口全部删除。首次未配对时的引导配对页不算入口。引用旧入口的文案同步改写，例如“请在主界面点「取消配对」”和“请在连接状态页切换”。

### 5. 设置、下载与历史页的转场（M14，UI-04）

- 设置页与首页下载页复用聊天的转场：Android 按 M07 从右侧滑入，入场可被右滑接管；iOS 沿用原生 push 入场。两端在页面内右滑按 M08 跟手、预测、阈值和回弹返回首页；底层为首页，保持同一组合身份，返回后可立即点击。设置页内的二级页（供应商管理）返回设置页。
- 聊天顶栏和历史页顶栏的下载按钮单独处理（历史页按钮见 §7）。它们打开的下载页同样从右侧滑入，在页面内右滑返回。返回目标是打开它的那个页面，不是首页；右滑时露出的底层也是这个页面。来源页面保持原实例，阅读锚点、跟随状态、草稿、展开状态和消息身份都不变；底层不能另建第二个聊天或历史页实例。首页、聊天、历史三个下载入口的返回目标互不串扰。
- r24：从聊天打开“历史与分支”页也复用上述转场，页面内右滑露出并返回原聊天，短拖回弹，保留阅读位置、草稿、工具展开与消息身份。iOS 通过 `push` 保存聊天画面快照并启用同一返回层；Android 历史页覆盖在常驻聊天组合上；历史内下载先返回历史，再由历史右滑回聊天。自动用例及手动 R19 见回归方案，未完成设备门禁不记为验收通过。
- r24：[ADR-0054](0054-shared-full-page-navigation.md) 将本节推广为所有下一级整页的默认规则，并取代逐页启用方式。新增页面通过共用导航容器继承效果；已配对后的添加电脑、Android 离线历史补齐同款返回，每次只退到直接来源。首次配对根页、Sheet / 对话框、目录抽屉及系统页面保持各自关闭方式。遗留供应商整页没有正常入口，本节原“设置页内的供应商管理二级页”仅规定未来整页恢复时的归属，不要求恢复旧入口。来源状态、平台差异与 R20–R22 见该 ADR 及回归方案；未完成门禁不记为验收通过。
- 减少动画时直接切换。手势起手和方向判定与目录抽屉（M09）、首页左滑关闭（M10）以及页面内横向控件（代码块横滚、文件 Pager）互不抢占。

### 6. 首页下拉刷新（M15，UI-05）

- iOS / Android 首页会话列表都支持下拉刷新：仅当列表在顶部时可以下拉；多选、左滑关闭和抽屉拖动期间不触发。触发后的逻辑与失败重试一致：已连接时刷新会话目录、Host 模型及全部 Runtime 模型，未就绪时重新连接（iOS `store.refresh()`，Android `refreshHome()`）。
- 下拉过程中列表内容随手指向下位移；iOS 沿用原生 `.refreshable` 滚动行为。Android 保留 Material3 `pullToRefresh` 手势状态，将 `distanceFraction × PositionalThreshold`（默认 80dp）应用到 `LazyColumn` 图层位移，不改变列表测量尺寸或滚动锚点；松手后列表和指示器回到原位。多选、左滑关闭与右滑打开抽屉的手势继续各自生效。
- 指示器只表示本次手势已触发，请求发出后收起；同步进度和失败仍由 S18 的连接胶囊或列表空态表达，不新增状态行。刷新期间保留上一版完整快照和视口位置（V18、V21）。Android 指示器继续使用 Material3 组件并配色跟随主题，不覆盖首卡阴影。
- Android 的 `isRefreshing` 只作为请求交接信号短暂置真，下一帧切回空闲以启动 Material3 收起动画；不得绑定 Host 同步完成或右上角状态更新。该修复记录于 ADR-0051 r22。
- Android 列表位移和指示器使用同一个 `HomePullRefreshState` 与回位弹簧；回位期间保持旋转，直到进度回到 0 后才隐藏，避免箭头停在阈值或与列表错拍。该修复记录于 ADR-0051 r23。

### 7. 下载飞入下载按钮（M16，UI-06）

- 在聊天页或“历史与分支”页点击下载（文件产物卡、Markdown 文件链接或其他会创建下载任务的入口）后，一个文件图标从点击位置飞向同页顶栏右上角的下载按钮。只有本地确实创建或排队了下载任务才起飞；未连接或被拒绝时不起飞，沿用现有错误提示。动画不能代表下载已经完成。
- 历史页顶栏右侧新增下载按钮，规格、角标和无障碍文案与聊天页一致，位于筛选按钮旁；点击后打开下载页，返回历史页（§5）。
- 初始参数：图标 28pt/dp，沿向上弯的二次贝塞尔路径飞行 520ms，缓入缓出，到达时缩至 16pt/dp，最后 80ms 淡出。目标按钮用 M02 弹簧（380 / 18）做 1 → 1.12 → 1 的轻弹，角标按实际任务数更新。参数最终值以实施时的明暗截图与帧序列复核为准，并回写 ADR-0051。
- 飞行层位于页面最上层，不参与命中测试，不改变布局、阅读锚点或跟随状态。连续点击时每次独立飞行，同时最多 3 个，超出的只轻弹按钮。拿不到精确点击坐标时（如 iOS Markdown 链接），以链接所在行或卡片的中心作为起点。减少动画时不飞行，只用 160ms 淡变高亮按钮。离开页面或切换会话时取消飞行，不残留浮层。

### 8. UI 回归门禁（立即生效）

- 任何 UI 功能实现，UI 设计、视觉、动效、布局变更，以及会改变显示的重构、性能优化、状态 / 投影 / 协议修复，完成前都要在共享池模拟器上执行 [UI 回归方案](../testing/ui-regression.md) 的自动回归和手动回归。自动回归包括单元测试、构建和完整设备 UI 套件；手动回归包括核心冒烟、受影响 ID 专项和外观矩阵。证据按方案记录。改了哪个平台就在哪个平台执行；改动基线规则、共用 token / 组件或双端共享的投影 / 协议时，两端都执行。
- 同一任务中，为新增或修改的 feature 编写或更新自动回归用例（逻辑用单元测试，布局、动效和交互用设备 UI 测试）和手动清单条目，并更新方案中的 ID ↔ 用例映射。只写设计、尚未改代码时，设计说明必须列出对应的自动与手动回归用例，实施时落地。
- 设备排队等待不算完成。未运行、失败或被环境阻塞的项目必须如实列出；只有与基线提交比较后不是新增的失败，才能单独登记为既有失败。纯文档改动只做编号、计数、链接和两个本机入口一致性检查。
- 一键执行全量回归的脚本（加池锁、构建、跑全量、比对失败）依赖本机环境，作为本机工具维护，不纳入仓库，由本机开发指南引用；仓库内的方案文档保留可手动执行的命令。

## Verification

本 ADR 和 ADR-0051 r15 修订为纯文档改动，只做编号、计数、相对链接和两个本机入口一致性检查，没有运行设备测试。§1–§7 的验收用例见 [回归方案](../testing/ui-regression.md) §5 与各 ticket；实施时逐项记录通过、未运行、失败和真实环境未验收的范围。

## Consequences

截至 r15 已交付的规则保持不变；r15 新增和修订的规则有了稳定 ID、ticket 与验收用例，实施者不必再从聊天记录中推断需求。r25 的 S23 / UI-07 将 Host RTT 显示加入设置页，具体数据和空值语义由 ADR-0050 与 ADR-0051 约束。回归门禁提高了每次 UI 改动的验证成本：完整设备套件和外观矩阵需要占用共享池设备。这一成本用于换取“动效、视口、身份不被静默回归”的可检验证据。
