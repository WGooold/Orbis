# ADR-0048：在线会话进入路径与首帧工作预算

日期：2026-10-30

Status: accepted（先记录决策，再测量和实施；两端实现及隔离模拟器回归完成，真机待复测）

关联：[ADR-0026](0026-host-selected-session-sync.md)、[ADR-0039](0039-content-change-signals.md)、[ADR-0046](0046-mobile-ui-stability-and-material.md)、[ADR-0047](0047-deferred-chat-disclosure-content.md)

## Context

用户在 ADR-0047 实施后仍报告：点击已在线会话，包括退出后再次进入，需要等约 1–2 秒。
闭合详情延迟构建的回归不能替代进入页面的端到端测量。本轮分别检查点击回调、页面首帧和首批正文，
不把远端同步完成时间混入首帧指标。

代码检查已经确认：

- iOS 首页卡片先调用带 Host 的 `selectRuntime`，随后 `ContentView.openRuntime` 再选一次。
  每次选择都整理消息、订阅 Agent state、强制核对 Session 和刷新 Git 信息。
- Android 在发布选择前刷新 Agent state；选择回调还持久化当前位置、检查历史链，
  `SwipeBackLayer` 入场时同时组合整个首页底层和聊天页。聊天列表初始位于第一项，
  再由副作用跳到末尾，可能先排版完全不会展示的历史。
- 两端按整个助手轮次组织懒加载行；很长的轮次及 Markdown 的实际构造/布局成本仍需测量，
  不能把上述代码现象直接解释成用户报告的全部延迟。

## Decision

1. 为隔离的在线、已缓存会话建立可重复的点击→选择返回→页面绘制/正文可见测量，覆盖首次进入和重入。
   使用单调时钟，记录耗时、消息数量和阶段，不记录正文、草稿或凭据。模拟器结果不冒充真机结果。
2. 一次用户打开操作只走一次包含 Host 身份的选择入口。选择及当前消息必须一致发布，
   远端核对不能作为导航前置条件；同一选择的非必要刷新应合并，并在页面进入后调度。
   延后任务必须校验当前 Host、Runtime、Session 和连接生命周期，不能把旧操作发给新的会话。
3. 首次布局直接定位当前已缓存内容的末尾，避免先排版顶部再跳转。继续遵守 ADR-0046 的像素距离跟随、
   用户阅读锚点及 ADR-0041 的分页边沿约束；不通过截断已加载正文或固定等待掩盖卡顿。
4. 保留聊天从右向左滑入、底层首页的过渡以及交互式右滑返回、回弹和首页原有状态。
   首页底层仅在入场或返回手势需要时构建；位移、压缩和遮罩随动画在绘制层更新，
   不在每一帧重新构建聊天和首页。不能以删除既有动效代替性能优化。
5. 根据测量继续消除首帧重复工作；保留不可变消息身份缓存及内容变更信号。
   不修改 Host 的源端事实、applied baseline、历史覆盖、事务租约或同步的正确性要求。

## Verification

- 记录同一夹具的优化前后时间，区分回调耗时、首帧和正文；至少覆盖长历史重入和长助手轮次。
- 确认一次点击不重复发起强制同步；快速切换和离开页面不会执行过时的延后刷新。
- 相关核心测试、原生构建及专用模拟器 UI 回归通过，验证返回手势、末尾定位、阅读锚点、分页和工具展开。
- 当前工作区有其他未提交改动，只修改本决策涉及的路径，不接触生产 Host 或用户真机。

## Consequences

会话导航具有独立的响应预算，不再由网络核对或无关首页重建决定何时显示页面。
首批正文的实际布局仍然需要执行；若测量显示长轮次仍超出预算，应继续按可见范围减少工作，
并记录尚未验证的边界，不能仅凭编译和功能测试宣称已消除 1–2 秒停顿。

## 测量后补充决策（实施前）

- iOS 独立模拟器夹具含 80 对历史消息和 80 条同轮助手消息。修改产品路径前，
  三次进入的点击回调为 7.1 / 5.5 / 3.7 ms，首次绘制为 1970.5 / 582.6 / 355.5 ms。
  首次绘制是应用 UIView draw 回调，不是显示器实际呈现，也不包含点击手势识别前的时间。
  该证据将本轮重点收敛到长轮次布局。嵌套懒布局试验破坏首次末尾定位，故不采用。
  两端改在外层懒列表将超过 4 条消息的助手轮次拆为连续卡片段，每段最多 4 条消息；
  保留原消息顺序/身份、完整正文、工具关联及计时归属，复制回复仍复制整轮。
  短轮次外观不变，长轮次出现连续卡片边界。这是为了真实虚拟化的明确呈现取舍。
  单条超长 Markdown 的排版仍有成本，不声称按消息分段能解决所有文本尺寸。
- Android 历史覆盖检查在显示窗口之前的每个节点上重新遍历祖先链，形成二次复杂度；
  用一次祖先集合计算替代逐节点遍历，保留分叉、缺口、循环防护和窗口边界的语义。

## 首轮实施结果（入场动效取舍已被下方修订替代）

- 两端外层聊天懒列表对长助手轮次分段，每段至多 4 条消息；复制动作持有整轮内容，
  工具结果和计时仍归属对应消息。历史补入时复用已有分段起点，避免阅读锚点因重新分组消失。
  单条超长消息仍使用现有渲染，没有截断正文。
- iOS 首页通过一个含 Host 的回调完成选择，删除第二次选择。Git 首次刷新由 ChatView
  现有任务负责，不在选择回调中再发一次。本轮没有引入额外的异步选择状态机。
- Android 聊天直接从缓存末尾首次布局；进入时立即显示页面，不组合首页底层。
  首页仍在真实返回拖拽时出现，松手后的回弹/返回动效及首页保存状态保持原有契约。
- Android 历史覆盖检查只遍历两条链（当前历史、显示窗口祖先），查集判断覆盖。
  状态写入调用带上一份已核对状态；历史和图的对象身份未变时，选择及无关状态更新跳过覆盖重算。

## 最终验证与证据

夹具包含 80 对历史消息、80 条同轮助手消息及末尾标记，共 242 条消息。
各平台在同一专用模拟器、相同夹具上比较修改前后，每轮三次进入；数字是样本而非 p95，
不能跨平台比较硬件速度或当成真机承诺。

| 测量 | 修改前（首次 / 重入 1 / 重入 2） | 修改后（首次 / 重入 1 / 重入 2） |
| --- | --- | --- |
| iOS 点击回调→UIView 绘制 | 1970.5 / 582.6 / 355.5 ms | 804.1 / 171.3 / 159.7 ms |
| iOS 点击回调自身 | 7.1 / 5.5 / 3.7 ms | 9.6 / 0.9 / 0.8 ms |
| Android 选择夹具→聊天绘制 | 724.3 / 382.1 / 210.2 ms | 304.1 / 111.1 / 90.2 ms |
| Android 4,000 节点覆盖核对（桌面 JVM） | 124.3 / 114.7 / 112.0 ms | 2.5 / 1.1 / 1.0 ms |

Android UI 夹具使用真实 ChatScreen / SwipeBackLayer，但直接提供已加载状态，不含 HostConnection
选择回调、加密或网络耗时；iOS 使用 PreviewTransport 和真实首页选择路径。
两端绘制探针都不测物理屏幕呈现、不含手势识别前的时间，也不表示源端同步已经完成。
Android 进入期间首页底层组合次数由每次 1 次变为 **0 次**。

- iOS：**178 项核心测试**通过，原生 Debug 构建及应用包动态依赖检查通过；**4 项 UI 回归**通过。
  进入测试确认末尾正文可点击命中、每次点击仅新增 1 次 Session 同步，首进小于 1200 ms、重入小于 500 ms。
  另覆盖长会话重入/工具展开、长回复阅读和跳到最新、闭合详情零构造及展开状态。
- Android：**482 项单元测试**通过，Debug / AndroidTest 构建通过；**9 项设备回归**通过。
  覆盖长会话进入/重入（绘制小于 500 ms）、无首页底层组合、返回手势/取消回弹、阅读锚点、
  内容更新和折叠详情。覆盖检查用计数 Map 验证 4,000 节点访问数不超过 8,000；仅切换选择时为 0，
  并验证分叉缺口和窗口起点缺失不会误判为已覆盖。
- 两端单元回归确认分段消息无丢失、复制整轮完整，以及历史前缀补入后已有分段起点保持不变。
  iOS 末尾截图已导出检查，最新正文和输入区正常可见。
- `git diff --check` 通过。测试仅使用专用模拟器和独立数据，未连接生产 Host 或操作用户真机。

本机证据位于 `.artifacts/chat-entry-perf/`：`ios-before.log`、`ios-final.log`、
`ios-final.xcresult`、`android-before-device.log`、`android-final-ui.log`、
`android-final-device.log`、`android-coverage-before.xml`、`swift.log`、`android-final-build.log`、`screenshots/`。
Android 客户端最终完整报告 `OK (9 tests)`，设备日志也确认 9 项通过。
`ios-lazy-turn.xcresult` 保存了被放弃的嵌套懒布局试验：它没有满足末尾可见性，未保留在实现中。

仍待真机验证：用户原会话的实际点击到可见时间、单条超长 Markdown / 多内容块消息、
后台持续入站时的主线程占用。当前证据说明上述已复现的布局和覆盖检查成本下降，
不代表已经在用户设备上确认全部 1–2 秒延迟消失。

## 2026-10-30 修订：恢复既有入场动效（实施前）

用户指出 Android 点击会话后原本从右向左滑入的效果消失。首轮实现将“避免首页底层重建”
与“取消入场动画”一并处理，改变了既有交互，本修订撤销该取舍并替代 Decision §4。

- 恢复原有从屏幕右侧滑入的弹簧动效，以及入场时首页底层的压缩和遮罩；不等待源端同步完成才开始。
- 保留长轮次分段懒加载、缓存末尾首次定位、线性历史覆盖检查和 iOS 去重选择等优化。
- 入场期间禁用返回拖拽，结束后恢复原来的右滑、取消回弹及松手后返回行为。
- 回归需断言初始在屏幕右侧、中间帧向左移动、最后归位；首页只在转场需要时存在，
  不能因每帧位移更新反复组合。重入也必须播放滑入效果。
- 重新运行长会话进入和返回手势测试、编译 APK。上文“无入场动效 / 首页组合 0 次”的测量
  仅保留为首轮历史证据；恢复后的结果另行记录，不沿用旧数字作为新版本结论。

### 修订验证

- 已恢复原有 `SwipeBackLayer` 入场实现，位移继续在 `graphicsLayer` 中读取；未回退消息分段、
  末尾定位或历史覆盖检查优化。
- 专用 Android API 35 模拟器 **8 项设备测试通过**：3 项转场/返回手势、1 项长会话进入/重入、
  4 项阅读位置和内容更新。新增转场测试冻结时钟，检查两次进入的初始屏外位置、80/160 ms
  中间帧向左移动、最终归位，以及每次入场首页底层只组合 1 次、结束后释放。
- 相同长会话夹具的绘制探针为 **295.3 / 74.4 / 75.9 ms**，首页底层每次组合 **1 次**。
  Compose 测试时钟会推进动画；这些数字仍然只说明渲染工作，不是弹簧完整播放的真实耗时。
- Debug 与 AndroidTest APK 编译通过，`git diff --check` 通过。没有操作用户手机。
- 证据目录 `.artifacts/chat-entry-animation/`：`build-final.log`、`ui-verified.log`、
  `device-verified.log`。最终客户端完整报告 `OK (8 tests)`，对应设备端记录为 8 项通过。
  `ui-final.log` 是修正测试暂停时钟后重入所需帧推进之前的失败记录，不作为最终结果。
- 修复版 APK：`.artifacts/chat-entry-animation/orbis-0.1.52-slide-in-debug.apk`，
  SHA-256：`1c0cc23d7afad3f24728f3c8f9b408bcc525ed08eb32b72b78a8749f63da9197`。

## 2026-10-30 基线归并：入场接管与首页身份

[ADR-0051](0051-ui-style-motion-and-visual-stability-freeze.md) 的 M07、M08、V13 收录 `ed8da5d` 后已经落地的行为，
补充并替代上方修订中的“入场期间禁用返回拖拽”和“入场结束后释放首页底层”两条描述：

- Android 入场允许被右滑立即接管；按住时停止入场，继续移动时页面跟手，不以源端加载完成为前置条件。
- 首页保留同一组合身份，聊天遮盖期间不逐帧重组；返回完成后立即恢复交互，不留下屏外透明聊天层挡住点击。
- 取消返回保留弹簧回弹，确认返回使用 180ms 退场。位移、底层压缩和遮罩仍在绘制层更新，既有入场不删除。
- 对应回归入口为 `SwipeBackInstrumentedTest`（含 `rightSwipeInterruptsEntranceBeforeLoadingFinishes`）
  和 `HomeNavigationInstrumentedTest`。这是本次对既有实现 / 测试的盘点，不是本次重新运行设备测试；
  上方旧耗时与首页释放结果不用于证明后续实现的性能或生命周期。
