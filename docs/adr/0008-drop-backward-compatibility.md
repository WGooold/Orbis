# 放弃协议向后兼容

**Status:** accepted

本产品目前**只有一个人使用**（作者本人）：需要升级的三个部件——Pi extension(`/reload`)、
已部署的 Relay（有部署脚本）、以及手机上的 APK（可重新构建并安装）——都在自己手里。
在这个前提下，维护"与旧版本互通"的能力**没有受益方，却持续制造缺陷**。本 ADR 决定把
向后兼容作为协议策略**取消**，并把它替换成一条硬版本门槛。

本 ADR 的前提是"单用户"。一旦出现第二个用户，这条决定必须重新评估（见 Trade-offs）。

## Context

### 兼容机制已经造出过真实缺陷

- **`ENVELOPE_CHANNELS_FEATURE` 只广播、没人读**：Relay 在 `runtime.ready.features` 里宣告
  `envelope.channels`（`packages/relay/src/index.ts:904`），但仓库里没有任何地方读它。
  于是"老中继会把 `hdr.ch` 吃掉"这件事**不是靠代码防的**，而是靠"先升级中继"的部署纪律。
  兼容机制最危险的形态——**静默降级**——已经发生过一次，只是没人注意到。
- **P2P 路径漏了声明**：`RelayClient` 在 HS1 里声明了 `channels`，`P2pTransport` 没声明
  （见 早期内部设计记录（不包含在公开仓库中））。
  这个 bug 只因为"要不要声明"这件事存在而存在——若所有路径无条件使用 channel，它不可能发生。
- **`ctl` 插队会静默丢弃 runtime 事件**（见 早期内部设计记录（不包含在公开仓库中））：
  接收侧用"单条有序流"的假设处理序号，而这个假设正是被"多格式共存"的排序规则破坏的。
  代码里给 `session.snapshot` 开的"允许过时序号"例外，就是这类补丁的痕迹。

### 规模

源码里"兼容/缺省/旧行为"一类痕迹约 **105 处**，协议里的 `optional()` 字段 **90 个**，
而全仓库线上 schema 的 `.strict()` 数量是 **0**。最后一项是关键：zod 对未知键的默认行为是
**静默 strip**，所以在这个项目里"不兼容"**默认是无声的**——没有人能确定自己正在跑哪条路径。

### 兼容代码的复合成本

每一条兼容分支都会让后续改动变成"设计一次协商"。例如给 `channels` 加能力，就得回答
"老对端不声明时怎么办"；而下一步要做的三件事（nonce 按 channel 分开、写入层切片、
分片道取序号）**每一件都要额外设计一次协商**，其中加密类的改动还**无法靠"两种都试"降级**。
这个矩阵只会继续翻倍。

## Decision

协议不再承诺与旧版本互通。

1. **`protocolVersion` 是硬门槛。** 不匹配即拒绝连接，报错必须可操作
   （"请升级电脑端"/"请更新 APP"）。不做版本范围内的双格式支持。
2. **"缺省 = 旧行为" 全部改为 "缺省 = 协议错误"。** 每条线上路径只允许有一种含义。
3. **线上 schema 一律 strict。** 未知键 = 拒绝，不再 strip。这同时消除"静默降级"这一整类故障。
4. **删除全部能力声明与双路径：** `channels` / `features` 协商、`mode` 的 pull/stream 双路径、
   `messageAttachments` 之类的可选能力位、以及一切"为旧对端保留"的分支。
5. **唯一保留的"兼容"是可读的升级提示**——它不是兼容代码，而是错误信息的一部分。

### 收掉中继上的明文会话面（扩展不再回落到中继）

中继原本还承接一种"运行时直连"模式：Pi 扩展在**找不到本机 Host** 时回落到中继，
中继把该连接的会话事件以**明文**广播给设备（中继解不开 E2E，而这条入口是运行时的直连入口）。
这与"中继零知识"的前提冲突，而且那条路本来也干不了活——命令是端到端发给 Host 的，
Host 不在就没人执行，手机只会看到一个"只能看、发不出命令"的半残进程。

决定：

- **中继只接受网关（`role: "host"`）。** 其它角色在 `runtime.authenticate` 处回绝
  （`runtime_role_not_allowed`），因此中继手里只有网关，没有"该播给手机的进程目录"
  （`device.ready.runtimes` 的种子恒为空，目录由 Host 自己给）。
- **中继不再转发运行时的明文事件**：`runtime.event` 一律回绝
  （`runtime_event_not_allowed`）。会话内容只能经 Host 的端到端通道到达设备。
- **扩展的唯一通道是本机 Host 的 loopback**；Host 没起来时**等它**
  （重连前重读发现文件，Host 起起来就自己接上），不回落到中继。
- 随之删掉的死件：`loopback.ping/pong` 探测（它只服务于"走 loopback 还是回落中继"的选择）、
  中继面向 agent runtime 的 `runtime.resync` 与 `runtime.online/offline` 广播。

**已知遗留**：扩展的配置仍要求 `relayUrl` 与 `runtimeCredential`，但它现在一个都用不到了
（loopback 描述文件自带 URL 与 token）。收掉这块死配置要动配对时的配置交接，留作后续。

## Consequences

### Positive

- 每条帧、每个字段只有一种含义，读代码不必再问"这是新路径还是旧路径"。
- **不兼容从静默变为响亮**：strict + 版本门槛之后，任何残留的旧格式会当场报错。
- 后续改动不再需要设计协商，直接改：
  - 03 的写入层切片可以直接采用"新 `k` 值"方案（老对端会响亮失败，而 strip 风险已被 strict 消除）；
  - 04 的分片道 nonce 派生可以直接改，不必设计握手级协商；
  - 05 自然消失（不再存在"声明 channels"这件事）。
- 代码量与心智负担同时下降（约 105 处痕迹 + 90 个 optional 的取舍空间）。

### Trade-offs

- **任何新旧混跑的窗口都变成硬失败。** 这条依赖"能重新构建并安装 APK"。
  如果某一刻做不到，唯一补救就是报错文案——**这一点必须先确认**。
- **中继必须先升级的部署顺序仍然存在。** 它不是协议兼容问题，而是三方结构决定的；
  strict 化会让它**响亮失败**而不是静默降级，这是改善，不是消除。
- **本决定的前提是单用户。** 出现第二个用户时，"能否强制所有人同时升级"重新变成开放问题，
  本 ADR 需要重开。
- 已配对设备在升级后需要重新握手（新版本号 + 新格式），这是预期行为。

## Verification

- 加 `.strict()` 之后全量测试通过，并且真机完整连一次（注册、下载、上传、交互）——
  用来暴露"其实一直靠 strip 活着"的地方。
- 版本不匹配时，两端都给出可操作的报错（而不是静默失败或不可读的解析错误）。
- 删完之后，仓库里不存在"缺省 = 旧行为"的分支；用一条测试锁死"新格式无条件使用"，
  防止旧路径再爬回来。
- `grep` 证据：`optional()` 字段数、兼容痕迹数、以及 schema 的 strict 覆盖率在改动前后可比。
