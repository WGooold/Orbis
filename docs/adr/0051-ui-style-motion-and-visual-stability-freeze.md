## Decision

### 1. 冻结含义与文档关系

- 本文是 UI 基线的统一入口；表中“冻结规则”是后续改动必须保持的行为，不代表本次重新完成了所有设备验收。
- 原专题 ADR 保留其背景、状态 / 协议细节和验证证据。本文汇总 ADR-0046 的全部 17 项要求，补入后续 feature；不废弃那些决策。
- 新需求可以演进基线。在用户已授权的任务范围内完成设计和修改，同时记录决策、影响与验证；不因“冻结”额外制造确认流程。

## Maintenance

根目录 `AGENTS.md` 与 `CLAUDE.md` 必须包含关键词和本 ADR 引用；两者保持 Git 忽略，不能为维护规则而强制提交。

1. 设计或改动前，先查关键词、相关 feature ID 和源专题 ADR；将受影响 ID 写入本次设计 / 变更说明。
2. 新 feature 先复用现有 token、组件和状态边界。确需新增、修改、删除、替代或调整参数时，在同一任务中更新本 ADR 的规则、适用平台、来源、验证与修订记录；新增 ID 追加，旧 ID 不复用。
3. 同步更新两个本机指南的基线版本、关键词、引用和维护说明；即使关键词不变，基线版本也须对应最新修订。影响专题契约时同步修订原 ADR，明确覆盖哪条旧决策；影响审计 / 对齐记录时更新其当前状态说明，保留历史证据。
4. **UI 回归门禁（r15 起必须执行，[D53] §8）**：任何 UI 功能实现，UI 设计、视觉、动效、布局变更，以及会改变显示的重构、性能优化、状态 / 投影 / 协议修复，完成前都要在共享池模拟器上按 [UI 回归方案][Regression] 执行自动回归（单元、构建、完整设备 UI 套件）和手动回归（核心冒烟、受影响 ID 专项、外观矩阵）。改了哪个平台就在哪个平台执行；改动基线规则、共用 token / 组件或双端共享投影时两端都执行。视觉检查明暗 / 窄屏 / 大字体；动效检查起始、中间、结束、取消和减少动画；稳定性检查刷新、长文本、分页、拖动 / 惯性、键盘和失败恢复。纯文档变更只检查编号、计数、相对链接和两个指南的一致性。
5. **同一任务写好回归用例**：新增或修改的 feature 须编写或更新自动回归（逻辑用单元测试，布局、动效、交互用设备 UI 测试）和手动清单条目，并更新回归方案的 ID ↔ 用例映射。只写设计、尚未改代码时，设计说明列出对应的自动与手动用例，实施时落地。设备排队等待不算完成。
6. 如需设备或构建，遵循本机指南中的共享设备池、独占锁、固定构建目录及证据保留规则；旧文档的“专用模拟器”只指独占借用池内设备，不授权新建或绕过配额。
7. 记录实际通过、未运行、失败和待验收项；用户已收到的产物路径和未解决失败证据继续保留。完成前核对 ADR、专题文档、实现和两个指南是否描述同一基线。
