# ADR-0029：会话读取操作的状态机与单写者归属

Status: accepted（核心读取迁移、本地检查与覆盖安装完成；两条 Codex 客户端重建验收通过；完整进程重开/UI 同边界验收仍有测试驱动缺口）

关联：[ADR-0013](0013-bounded-session-sync-and-shared-tree-ingestion.md)、[ADR-0024](0024-recoverable-session-state-sync.md)、[ADR-0025](0025-native-history-authority-and-versioned-caches.md)、[ADR-0026](0026-host-selected-session-sync.md)、[ADR-0028](0028-host-notification-lifecycle.md)。

APP 用显式状态机表达一次会话读取操作的生命周期，以单写者协调器拥有操作状态与迁移权限；UI 使用单向数据流请求和观察操作，异步工作通过结构化并发执行。统一的是身份、归属、接力、失效和终态，不是把打开、当前状态恢复、历史分页及后台 catchup 串成一个阻塞任务。原生历史权威、统一事务写入、源端版本和有界同步协议继续遵守关联 ADR。

## Context

迁移前，一次上滑可能经过 UI 锚点、本地 history Job、远端 history 请求、持久化、reducer 和 UI 收尾。它们没有贯穿全程的操作身份：本地 Job 在 ViewModel 的 map 中，远端任务在同步任务表中，显示状态只有 loading 和远端 requestId，UI 再根据 loading 或列表增长推断结束。首屏与刷新还使用另一个合并装载器和刷新意图集合。

真机诊断已观察到：本地读出 30 条历史，设备、选择、Session、leaf 和分页边界仍匹配，但 loading 已变为 false，结果随即被拒绝；读取约几十毫秒，不是长时间锁等待。确切清除 loading 的并发写入者尚未确认。代码审查另发现完成回调、投影初始化、连接/目录重置等会修改共享分页状态，以及范围失败扩大为 Runtime 失败、离线读失败被当作到底、UI 无接受反馈等问题；不能把所有风险都说成已复现或同一个根因。

远端已有稳定任务身份、有限重试和迟到关联，缓存已有来源/epoch/结构校验。缺少的是把这些机制连接起来的操作契约，而不是增加更多布尔字段、删除归属检查或扩大锁范围。

## Decision

### 1. 操作、执行任务、数据事实和显示状态分开

**会话读取操作（Session read operation）**是 APP 为一次明确读取或核对目标建立的逻辑生命周期。一次操作可以执行本地查询、一个或多个远端范围任务及投影，但不等于其中任意 Job、网络尝试或源端版本。

| 概念 | 职责 |
| --- | --- |
| 首屏读取 | 提供有界的可显示范围；不等待完整历史或后台 catchup |
| 当前状态恢复/核对 | 确认或重建 Applied Session state，遵守 preview 条件响应与源端恢复规则 |
| 历史分页 | 查询固定显示分支、固定旧边界之前的有界范围；本地优先，必要时远端接力 |
| 固定目标 catchup | 补齐到固定目标所需的缓存缺口；不能由页面到达顺序移动当前 head/live |
| 执行任务 | 为操作执行一次读取、范围请求、等待或提交；重试不改变该范围的参数 |
| 数据事实 | Session Tree Cache、Continuous coverage、Applied Session state；各有独立验证条件 |
| 显示状态 | 消息投影、等待提示和视口锚点；观察操作与数据事实，不反过来赋予任务有效性 |

打开会话可以同时产生首屏读取、当前状态恢复和后台补齐需求，它们不是一个必须全部完成才可显示的操作。Pi、Codex、DSH 以及离线阅读遵守同一客户端契约，原生差异仍由 Agent backend 负责。

### 2. 显式状态机与唯一迁移权限

使用显式、可分层的状态机表达接受、执行阶段、接力和终态。历史分页的典型阶段为“已接受 → 本地读取 → 必要时等待远端页 → 应用结果 → 终结”；catchup 可以按固定目标执行多页，当前状态恢复可以按源端未知/部分结果继续有界恢复。不能把这个示例强制套成所有操作的一条线性流程。

一个操作有独立于 loading 的稳定身份；执行结果、完成回调、超时和取消事件都携带该身份。拥有者校验操作仍有效，才能迁移状态。旧任务不得结束新操作，重复事件不得重复收尾，已经终结的操作不能被迟到结果复活。

协调器是 APP 操作状态的单写者：入口提交意图，IO 和网络提交有身份的结果，目录、连接和源端状态变化提交明确的失效事实。reducer 可以承担纯状态迁移，Actor/事件循环可以承担事件排序；不要求引入 Actor 框架。现有 ViewModel、Job 回调、缓存投影和 Compose 不得绕过拥有者直接修改操作状态。

这不增加第二个当前聊天状态写入者。源端 checkpoint/patch 仍按既有版本门槛应用；协调器消费已接受的数据事实并管理读取操作，不能以本地操作版本替代 source epoch/seq。

单写者不等于单线程阻塞全部工作：IO 可以并发，返回结果后串行判定归属。共享 Session 数据与各 Runtime/离线窗口的显示状态有不同作用域，不能仅以 Session ID 或当前选中 Runtime 概括全部归属，也不建立每种页面或后端各自的一套独立拥有者。

### 3. 分开验证操作、缓存写入与视图应用

操作登记目标与相关上下文：配对 Host/设备缓存命名空间、Session、视图或 Runtime、分支代次、范围、固定目标和分页边界。远端执行任务继续绑定连接代次、commandId/syncId、不可变范围参数及固定 knownState；已知的缓存/source epoch 按现有协议校验，恢复握手中未知的 epoch 不通过猜测填充。

以下资格分别判断，不能用一个 loading 代替：

1. **操作仍有效**：拥有者身份和目标未被取消或替代。
2. **数据可提交**：请求、来源、epoch、范围和结构验证通过，并满足统一事务写入要求。
3. **结果可显示**：视图仍属于相应 Session/分支，且应用不会回退较新的已确认状态。

窗口离开只表示不再需要该窗口的前台操作，不自动证明所有缓存补齐需求失效。若数据在原窗口退出后仍要接收，必须由事先保留的、有界后台操作明确拥有；不能事后把失去归属的响应包装成后台任务。已取消、被替代或旧连接/旧 epoch 的响应仍按 ADR-0013/0025 拒绝写入，不能因为“缓存也许有用”绕过检查。

同分支的正常追加、普通刷新、unchanged 确认和显示投影更新不是分页取消理由。合法的固定旧范围不依赖实时 leaf 停留不变；历史页也不能移动当前 head/live。原生分支/epoch 替换、Session 更换、配对失效或明确替代按对应作用域使任务失效。

### 4. 本地/远端接力与结构化并发

本地查询和远端补页是操作内部的执行阶段。缓存不足时，拥有者先登记接力，再结束本地阶段；本地 Job 的完成回调只能报告该执行任务结束，不能凭 requestId 是否为空清除共享等待状态。

执行任务使用明确的父子作用域。取消操作时停止其后续调度并清理可取消的子任务；已发出的远端请求即使不能物理撤回，返回结果也必须重新验证归属。独立操作使用隔离的失败与取消作用域，某次分页失败不能通过父作用域意外取消其他 Session 或仍有效的后台补齐。

区分“取消执行”“拒绝结果应用”和“通知等待结束”。失效时由拥有者记录原因并完成收尾，不能只重置 loading，也不能只 cancel Job 而不通知调用方。

连接变化仍结束或重建绑定旧连接的远端任务；是否继续纯本地读取，取决于其配对、缓存和视图归属，而不是连接显示文案。允许继续的本地操作必须重新验证这些事实，不自动接纳旧连接响应。ViewModel/进程结束终止内存操作；重开后从持久缓存和新的源端核对恢复，不持久化 loading 或继承旧 Job 身份。

### 5. 接受反馈、终态与迟到恢复

入口明确返回接受、合并到已有操作或拒绝，并提供可关联的操作身份；拒绝包含可处理原因，不创建假等待。被接受的调用方必须能够观察该操作的当前状态和终态，不依赖恰好订阅到一个瞬时事件。

终态区分成功、历史到底、失败、取消和被替代；具体结果与操作类型匹配。读取失败、源端未知、空局部页或没有新增显示行，都不能当作历史到底。到底必须由有效查询或响应明确证明。

每个操作在同一客户端生命周期内只产生一次逻辑终态。远端重试继续遵守 ADR-0013/0026 的稳定关联、有界退避和不可变参数，成功 command.result 不代表数据已经送达或提交。

保留现有有界迟到恢复能力，但不把它实现为“已终结操作重新成功”：超时结束本次等待后，拥有者可以保留明确的响应关联和恢复资格；仍合法的迟到响应由独立恢复操作处理，不再通知原操作第二个终态，也不能抢占已替代它的新操作。被取消、目标失效或显式重试已替代的关联不具备这种资格。恢复资格及关联记录都要有上限和清理条件。

### 6. UI 单向观察，刷新需求按目标完成

Compose 提交读取意图、观察操作状态和数据投影，不直接改变生命周期。loading 从当前操作推导，不再作为结果归属凭证。视口锚点属于具体视图及其操作：只有接受后才等待，或在拒绝时立即撤销临时锚点；成功、到底、失败、取消和替代都有释放路径，不能要求列表数量增加才收尾。

UI 退后台停止前台周期意图，不等于终止所有后台工作；切换窗口结束相应前台归属，独立后台 catchup 可以继续。局部完成、loading 或锚点变化不能清源端恢复需求或无关操作。

刷新需求记录要满足的目标和需求代次。操作只消耗它实际确认的那一份需求：读取结束不证明 Applied Session state 已恢复，一页提交不证明固定目标已覆盖，较早操作完成也不能清掉执行期间产生的新需求。同目标请求可以合并，但不能用新的范围或 knownState 修改已有远端任务参数；目标改变需要新操作或后续一轮。

### 7. 本地优先 Repository 与失败作用域

缓存查询、统一 ingestion 和显示投影通过清晰的模块接口协作。首屏/历史读取优先使用有效缓存；已有可信 Applied Session state 的周期核对按 ADR-0026 直接请求源端，不先重复解密本地 tail。Repository 不成为另一套操作拥有者，也不新增各页面私有写库入口。

原生历史仍是权威，SQLite 是受来源与版本约束的副本。首屏可显示、Continuous coverage 完整、Applied Session state 已确认是三个不同事实。保持事务成功后才发布对应投影和已应用版本；epoch 切换、非法结构和失去写入归属仍须原子拒绝或回滚。

失败按本地读取、持久化、远端范围、源端基线和连接/认证等作用域处理，严重程度不等于作用范围。某个 history/catchup 失败不能默认锁死 Runtime 的所有读取；源端不可用也不自动否决仍通过验证的本地历史。配对/授权失效或已确认缓存不可用等真正共同原因才扩大限制，必须有明确依据。

APP 本地读取提示由操作状态拥有；远端 Runtime notification 继续遵守 ADR-0028 的独立来源和生命周期。分页成功不能清无关通知，通知关闭或到期也不能把读取失败改为成功。

## Alternatives and consequences

- **只移除 loading 校验或补 guard**：可能修正一个丢弃点，但不能解决旧回调结束新任务、接力归属、拒绝反馈和离线收尾；保留必要校验，改变其依据。
- **扩大 Mutex 范围**：能减少交错，却不定义结束权限，会把耗时 IO 变成全局阻塞；采用单写者迁移和带身份的并发结果，而不是一把长时间持有的大锁。
- **只改 MVVM/MVI、只抽 Repository 或只用结构化并发**：分别改善分层、数据访问或执行资源，但单独不建立完整的操作归属与终态契约。
- **所有读取共用一个大任务**：会使首屏等待后台补齐，或窗口切换误取消仍有效的缓存工作；统一契约，不统一所有目标和寿命。
- **持久化工作流引擎或 Event Sourcing**：当前没有跨进程保存每次读取阶段的需求；采用有界内存操作状态，继续依靠缓存和源端恢复，不新增永久任务日志或第三方框架依赖。

代价是需要集中迁移现有状态写入入口，并处理操作、执行任务和远端迟到关联的关系。收益是正确性集中在一个深模块：调用者只表达目标、观察结果，不再各自维护取消、接力和收尾规则。模块拆分不能只增加一层转发而保留原有多写者。

本 ADR 补充 APP 的操作管理，保留关联 ADR 的权威、预算、协议、事务及通知决定；不改变 Host/Relay 职责，不承诺网络恰好投递一次，不将手机变成原生历史权威。优先复用现有协议；若实施确需修改线上 schema，另行记录变更并遵守 ADR-0008。写入 ADR 不授权行为实施、清缓存、修改用户会话、安装、Host 重启、push 或发布。

## Verification and implementation boundary

后续实施先建立最小、可控的竞争复现，再迁移拥有者和本地/远端接力，移除绕过路径，最后接入 UI 与失败分类。本 ADR 不指定类名、字段布局或 Actor 库；实现必须满足以下行为不变量，而不是只让示例状态图或内部字段测试通过。

| 场景 | 必须保持的行为 |
| --- | --- |
| 本地分页期间普通刷新或同分支追加 | 有效旧页仍能应用；当前 head/live 不被历史页回退 |
| 旧执行任务迟到完成，新操作已开始 | 不能清新操作等待或终态，不能改新窗口的边界 |
| 缓存不足转远端，命令先确认、snapshot 后到 | 接力保持同一操作归属；仅 acknowledgment 不结束读取 |
| 拒绝、空页、到底、异常、取消、替代 | 调用方得到准确结果，在线与离线锚点均能释放并再次请求 |
| Session/分支/epoch 替换，旧结果迟到 | 不污染新缓存、投影、coverage 或已应用基线 |
| 超时后合法迟到页；显式重试后旧页 | 保留有界恢复而不重复原操作终态；被替代响应不能抢占新操作 |
| 远端范围失败，本地缓存仍有效 | 失败隔离；本地读失败不伪报到底，也不清其他操作/通知 |
| 操作执行期间新增刷新需求 | 旧完成不吞新需求；重试参数稳定，多页固定目标不漂移 |
| ViewModel/进程重建、断线或窗口切换 | 不继承旧等待；严格隔离旧连接响应，按有效缓存和源端事实恢复 |
| 缓存写入或 epoch 切换失败 | 事务回滚，已应用版本与显示不先于持久化事实推进 |

按一个不变量一个用例组织最少回归钉子，优先并入已有生产方测试；相同契约不在每个后端和页面重复固化。已有真机丢弃证据需要转为确定性竞态测试；代码风险、测试通过、完整进程重开/UI 上滑验收及用户环境生效分别记录。ADR 采纳时尚未实施这些机制；后续迁移及验证范围见下节，未验证项目不能视为已完成。

## 首阶段实施记录：历史分页

最初的分页操作实现现已并入 `SessionReadOperations.kt` 的统一客户端逻辑操作与纯状态迁移接口：操作登记、合并/拒绝、归属检查、本地结果应用、远端接力、终态和有界迟到恢复由该模块处理。ViewModel 的本地 worker 使用操作身份注册后再启动，完成回调只清理自身 Job；普通显示重建的 loading 不再决定任务有效性。缓存缺口与读取异常分开，离线失败保留再次请求资格。远端 task 继续沿用既有 command/syncId 和范围参数，没有线上 schema 变化。

`SessionSyncTasks` 与 reducer 已接入 history 操作关联。history/catchup 范围失败记录为局部错误，不再默认写入 Runtime 基线恢复失败；队列满不会终结无关本地页。超时结束原操作后，仍合法的迟到响应由新恢复操作接收；显式重试、归属改变或新操作替代后，旧关联不得抢占。在线和离线 Compose 按接受反馈及对应操作终态收尾，失败不自动循环请求，并提供明确的历史重试入口。

关键入站 reducer、快照应用和选择入口改为基于最新状态发布，避免读取旧状态后覆盖并发登记的 history 操作。此处记录的是历史分页首阶段的边界：当时首屏/离线首次读取、preview 恢复、跨页 catchup、刷新需求代次与装载器队列尚未统一。后续统一迁移见下节，不将首次阶段的检查结果冒充后续改动的验证。

验证：

- Windows Android 构建入口运行 `:app:testDebugUnitTest :app:lintDebug --console=plain`，退出码 0；42 个测试文件、383 项单测通过，failure/error 为 0。lint 无错误、25 个警告。构建 daemon 已停止，资源 lease 已释放。

## 统一读取迁移：代码与本地检查

后续已将以下路径接入同一操作拥有者，不再停留在历史分页的局部机制：

- `SessionReadOperations.kt` 使用一个 `sessionReads` 操作表管理首屏、源端恢复/核对、历史分页和固定目标 catchup。历史类型别名与只读观察接口只是兼容调用者，不维护第二个可变 registry。操作终态不复活，合法迟到恢复登记独立操作与新的等待预算。
- ViewModel 的状态发布均经过基于最新状态的 `updateState`；唯一 StateFlow 赋值在这个短写者临界区内。目录、缓存查询及 ingestion 的 IO 不放进该临界区；已有统一事务入口、写入 guard、epoch/版本/范围检查和提交后投影规则继续保留。
- 在线和离线首屏通过带身份的本地查询与应用接口处理。查询把范围、缓存 epoch 和行版本作为同一次缓存观察读取；旧缓存结果不能覆盖较新的版本或回退已观察 leaf。有效缓存可以在源端状态未知时显示，但不提升 sourceReady/seq、不能伪造 Applied Session state，也不能清独立源端错误。
- 首屏与历史 worker 先登记执行句柄再启动，复用同一个按操作 ID 清理的 Job 表；窗口/分支/缓存失效取消所属 worker，旧 completion 只能移除自己的句柄。首屏 IO 和源端核对独立执行，不阻塞整个装载队列；ViewModel 结束终止内存操作。缓存格式迁移同时失效 Runtime 和离线窗口的分支代次，包括没有 epoch 的旧缓存。
- preview 的部分/未知响应结束单个范围请求，但保留同一 SOURCE 操作继续恢复。成功 ACK 或任务表删除不证明完成；只有合法关联的已提交响应或已恢复的数据事实才能确认。逻辑恢复预算覆盖连续部分响应，避免每页创建新任务而无限延长等待；协议重试仍保留原 command/syncId、范围和 knownState。
- catchup 跨页沿用同一固定目标；普通 live tail 更新和窗口离开不替换有效后台目标。持久缓存证明目标覆盖后才成功，再调度较新的目标。页到达而缺口参数没有推进时记录局部失败，不无限生成新任务；history/catchup 成功或失败均不能冒充独立源端基线的恢复。
- 刷新意图有需求代次，远端任务捕获不可变代次。旧响应只消耗它实际确认的需求，执行中新增需求保留后续一轮；取消、断线和目录移除不被当作成功完成，也不会重新恢复已撤销的意图。较早源端失败不能吞掉更新需求。选择和需求登记基于同一最新状态，避免把新 Session 的需求交给旧目录快照。
- `SessionLoadQueue.kt` 原子合并请求、取批和交接 worker owner token。新请求不能落在正在退出的 worker 后面，旧 finally 不能释放新 worker；当前窗口优先，取消或失败时仍保留可继续调度的队列请求。
- UI 的首屏/当前状态等待观察操作 phase，历史锚点与刷新锚点绑定各自的操作身份。成功、失败、取消、替代和无新增显示行都有释放路径；后台 catchup 不延长另一个前台操作的等待。源端数据完整性字段仍独立用于已应用基线判断，不再作为 UI 读取拥有权或 spinner 的凭证。

## 真机验收与有界范围修正

经用户本次授权，在原手机覆盖安装 App 与测试 APK，保留 App 数据、缓存和配对，只读既有两条 Codex 会话。最新客户端重建测试为 `OK (1 test)`：包含预热的 16 次分页、其中 12 次同 Session/epoch/leaf/边界的重建后缓存对照，全部本地完成、无 history 远端请求。最新耗时为 22–62 ms；同时观察并断言没有 `limit_reached` 范围失败。

真正进程关闭重开与 UI 上滑是独立验收。早前一条 Codex 完成了 3 次重开、6 次同边界本地读取；扩展到两条后，自动分页会在脚本开始计量前已读下一页，造成第二个捕获页边界漂移或没有捕获到起点。最新脚本仍报告 `INCONCLUSIVE`，不是全量通过，也不把没有触发/捕获分页的脚本等待判为 App 故障。脚本解析 UI XML 仅在内存进行，新增用户所报范围错误的专门检查，未在该轮观察到此错误。

用户随后报告频繁出现 `Session 范围加载失败：limit_reached`。确定性 reducer 回归复现了相同错误：客户端把 `complete=false && hasOlder=false` 同时用于 history 与 catchup 的失败判定。协议的 catchup 从已知节点向固定目标向前补齐，达到页条数/字节上限时正常返回 `limit_reached`、`complete=false`，而 `hasOlder=false` 只描述反向历史分页，不能证明向前补齐失败。手机脱敏日志也观察到实际 catchup 的 `limit_reached` 响应；不记录正文或路由标识。

修正仅将这项矛盾标志检查限于 history：保留非法范围、来源/epoch/结构校验和无进展保护。一个回归用例验证有界 catchup 页保留数据并继续同一目标，下一页覆盖完成后才成功，且不改变 head/live。更新后完整检查为 43 个文件、388 项 Android 单测通过，lint 无错误；修复版已覆盖安装。原错误的确定性复现已转绿，但这不替代仍有缺口的完整 UI 同边界验收。
