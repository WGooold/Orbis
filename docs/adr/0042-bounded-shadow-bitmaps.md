# ADR-0042：柔影按「角块图集」缓存，不再每帧生成硬件模糊蒙版

日期：2026-10-23

Status: accepted（2026-10-23 实现并真机验证：`RenderTarget` 从 186–251MB 降到 9–20MB，`GL mtrack` 从 226–290MB 降到 31–42MB，PSS 从 610–816MB 降到 346–366MB；卡片区域逐像素对比平均差 0.033/255、最大 16，柔影外观不变）

关联：[ADR-0040](0040-bounded-inbound-delivery.md)

## Context

2026-10-23 在同一台真机（Redmi 2407FRK8EC）上，除了 Java 堆 OOM（ADR-0040），还量到第二条独立的内存增长：**GPU 渲染目标**。

- 进程刚启动：`dumpsys gfxinfo` 的 `RenderTarget` 15.2MB / 24 个。
- 打开会话、滚动、停留在会话页约 5 分钟：186MB / 254 个，其中 227 张是 `1536x512` 纹理。
- 再约 4 分钟（期间只有流式内容和 1 秒计时器在重绘）：251MB，`GL mtrack` 251MB，PSS 610MB。
- 修复 Java 堆之前，同一增长路径最终到 440MB（578 个渲染目标），进程 PSS 1.2GB 被系统 SIGKILL。

`1536x512` 约等于一张聊天卡片的像素尺寸，而卡片上唯一会产生离屏纹理的绘制就是新拟物柔影：
[Neumorph.kt](../android/app/src/main/java/dev/pi/remote/Neumorph.kt) 的 `drawOuterBlur` / `drawInnerBlur`
把带 `BlurMaskFilter` 的 `Paint` 直接画在硬件加速的 `Canvas` 上。每个 `NeumorphSurface` 每帧画两次模糊
（dark + light），而 HWUI 为模糊生成的是**蒙版纹理**；卡片尺寸随内容变化，缓存键不断变化，纹理只增不减。

## Decision

### §1 柔影渲染成与尺寸无关的「角块图集」

每个 `NeumorphSurface` 的柔影（`Raised` 的 dark+light、`Pressed` 的内阴影）渲染进一张小位图：

- 位图里的形体是一个 `2·block` 见方的圆角方块，`block = 圆角 + 外扩`，外扩
  `margin = ceil(offset + 3·blur) + 2`；位图边长 `2·block + 2·margin`（典型约 200×200）。
- 绘制时九宫格贴回：四角原样贴到控件四角，四边只沿一个方向拉伸，中心用 1px 实色拉伸。
  高斯模糊对直边是平移不变的，所以拉伸出的边与原图逐像素一致；角块根本不缩放。

### §2 图集按材质缓存，与尺寸无关

键只有 `(圆角, 位移, 模糊半径, 风格, 两支画笔颜色)`，上限 8 张；正常最多 4 张
（浅/深色 × 凸起/凹陷），每张约 160–250KB。滚动过多少张卡片、卡片高度如何变化都不再产生新纹理。

### §3 失败回退

位图分配失败（OOM/非法尺寸）时回退到原来的直接模糊路径，并记 `Log.w`；不让绘图崩溃。
`API < 28` 或控件小于两个角块时同样走原路径（后者几乎不出现：圆角半径不可能大于控件短边的一半）。

### §4 不改的东西

- 不改配色、几何、圆角、阴影强度与 `BlurMaskFilter` 的半径；
- 不改 Compose 结构（仍是 `drawWithCache` + `onDrawBehind`），不改 `NeumorphSurface` 的布局语义。

## Consequences

- GPU 渲染目标不再随「见过的卡片尺寸数量」增长；稳定在图集对应的几张纹理上（实测 9–20MB）。
- 每个 surface 每帧从「两次全尺寸硬件模糊」变成「九次贴图」，总绘制量更低；首帧只多一次小图集渲染。
- 图集是 CPU 位图，占用可忽略（≤ 2MB），不再有「每张卡片一张位图」的 LRU 抖动。
- 若同一界面同时使用超过 8 种圆角/配色组合，缓存会淘汰；当前设计系统只有 2 套配色和 3 种圆角。

## Verification

- 设备实测（Redmi 2407FRK8EC，同一会话滚动 24 次后）：
  - `RenderTarget`：改前 186–251MB（254–578 个）→ 改后 9.25–19.55MB（14–17 个）；
  - `GL mtrack`：改前 226–290MB → 改后 31–42MB；
  - `PSS`：改前 610–816MB → 改后 346–366MB；
  - `Dalvik Heap`：14–32MB（ADR-0040 生效后）。
- 外观：同一列表页改前/改后截图逐像素对比（卡片区域），平均差 0.033/255、最大 16（文字抗锯齿），
  柔影颜色、扩散范围、圆角一致。
- 单元测试与 `:app:assembleDebug` 通过；长会话滚动无新 OOM/被杀记录。
