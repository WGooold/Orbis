## Context

### 实施前已确认的实现与问题

以下记录本决定之前的代码行为；本地新实现已替换工具载荷路径，具体符号和验证见[实施记录](../architecture/tool-content-implementation.md)。

1. Codex 的 `liveMessages` 和 `liveTools` 分别保存工具调用消息和工具状态，`#liveCheckpoint` 将两者完整放入 `session.patch`。参数可能同时出现在消息的 `tool_call.arguments` 和工具的 `detail.arguments`；输出增量累计到 `detail.output`。对应实现为 [`codex-runtime.ts`](../../packages/host/src/codex-runtime.ts) 的 `#handleNotification`、`#liveCheckpoint`、`#publishSourcePatch`。
2. Codex `#completeItem` 按原始 item 顺序提交历史。前序 item 未完成时，后续已完成工具仍属于 live。该规则保证实时构造与历史重建的顺序和 parent 一致，但完整参数与结果因此可能长期留在每份 live checkpoint 中。
3. 通用同步选择器在没有加入历史 Entry 时就测量 snapshot；超过正常页预算会报 `session_metadata_too_large`。当前源码的正常页预算是 512 KiB，单响应硬上限是 1 MiB；见 [`session-sync.ts`](../../packages/protocol/src/session-sync.ts) 的 `SESSION_SYNC_PAGE_BYTES`、`SESSION_SYNC_MAX_BYTES` 和 `selectPreparedSessionSync`。Registry 默认单值上限也是 1 MiB，超限返回 `value_too_large` 并拒绝提交；见 [`agent-state-registry.ts`](../../packages/host/src/agent-state-registry.ts)。两者是不同检查点。
4. App 已将工具结果合并到工具调用卡片，默认折叠，展开后才展示参数与结果；折叠不减少同步字节。见 [`MessagePresentation.kt`](../../android/app/src/main/java/com/orbising/orbis/MessagePresentation.kt) 的 `buildConversationPresentation` 和 [`MainActivity.kt`](../../android/app/src/main/java/com/orbising/orbis/MainActivity.kt) 的 `CollapsedTool`。
5. 现有 `session.entry.request` 从 Host 当前会话状态读取整条 Entry，一次返回完整响应；没有单条内容分页，也不能读取尚未提交的 live 工具。超过 1 MiB 返回 `session_entry_too_large`。见 [`host-service.ts`](../../packages/host/src/host-service.ts) 中该命令的分支。
6. `toolResultForItem` 尚未读取 Codex 的 `aggregatedOutput`，但 ADR-0038 的原生实测记录确认存在该字段。结果采集不完整是独立缺陷；仅补字段会增加当前同步载荷，不能替代本设计。

上述事实说明：工具的执行事实、聊天显示摘要和完整内容目前混在同一同步载荷中。需要改变数据归属和读取契约，而不是继续依靠默认折叠、增加快照上限或缩短输出前缀。

### 已做实验及其证明范围

2026-10-26，在主工作树使用真实 `CodexRuntime` 与同步实现、模拟 app-server 通知做了五类控制实验。测试文件是主工作树当时未提交的 `packages/host/src/codex-live-size.test.ts`，不在本 ADR worktree 的提交基线内；以下为实验记录，不是用户原故障的现场统计。

| 模拟场景 | live JSON UTF-8 字节 | 结果 |
| --- | ---: | --- |
| 16 个顺序完成的工具，每个输出 80 KiB | 峰值 82,397 | preview 成功，工具逐个提交后移出 live |
| 前序消息未完成，8 个后续工具已完成，每个结果 80 KiB | 659,047 | `session_metadata_too_large` |
| 单工具累计 600 KiB 输出 | 614,886 | `session_metadata_too_large` |
| 单助手消息累计 600 KiB 正文 | 614,655 | `session_metadata_too_large` |
| 单 MCP 工具的结构化参数在消息与工具状态中各存一份 | 621,327 | `session_metadata_too_large` |

实验证明工具数量、单项输出和重复参数都可以独立制造超大 live；也证明只处理工具不能解决超长助手正文。没有证据确定上述哪一种就是最初故障的实际触发条件，不将这些数字作为生产带宽节省比例。

## Decision

### §1 分离工具摘要、内容引用和原始内容

所有已支持后端采用同一模型，App 不按 `agentKind` 解释原生工具结构。

| 对象 | 归属与用途 | 默认是否同步 |
| --- | --- | --- |
| 工具摘要 | Host Agent state model 中的执行事实及历史显示投影 | 是，受条目、页和库存预算限制 |
| 内容引用 | 定位当前 Session 中某次调用的参数、输出或最终结果 | 是，只包含身份和可用性描述 |
| 原始内容 | 原生持久历史；必要时由生产者保留的有界临时内容存储 | 否，设备显式读取时返回范围 |

原生 Agent 仍消费和保存自身完整工具结果；本决定不改变模型上下文、工具执行参数、执行结果或原生历史。改变的是 Orbis 对外投影以及 Host 通用状态中的载荷归属。

摘要必须在进入 Host conversation state、Registry、共享事件分发以及 Pi→Host loopback 之前生成。只在 Host→App 出站时删字段，仍会让 Host 内部复制和 Registry 预算承受完整原文，不算完成本 ADR。

### §2 工具不再作为独立的完整结果聊天消息展示

App 在助手轮次内按来源确定的顺序显示紧凑的工具活动，可折叠连续工具活动组。正文、思考和工具活动的相对位置由 Host 的显示投影声明，不将全部工具统一移动到轮次末尾。

- 默认显示工具名称、可证明的操作对象或短命令摘要、运行阶段；结束后显示已确认的结果状态。
- 耗时、退出码、文件变更数量等只有在来源提供时显示。未知不写成 0，不用输出文本猜成功、失败或进度。
- 失败调用在折叠状态仍有明显标记和有界错误摘要，不自动展开或下载全部 stderr。
- 不自动展示 stdout、完整 diff、完整 MCP JSON 或大段调用参数。成功工具可以只保留状态与数量，不从原始输出生成未经验证的自然语言结论。
- 点开某次调用进入详情页，再按需读取“参数”“执行输出”“最终结果”。当前无对应部分时不显示空的成功结果。
- 审批、用户输入请求和阻塞性交互继续走独立交互模型；其必要参数不能因工具摘要化而被省略。

### §3 摘要字段与确定性

逻辑身份为 `(Host, agentKind, sessionId, toolCallId)`；来源能证明时增加 `turnId`、所属消息和历史 Entry 引用。运行时路由 ID 不作为持久工具身份。

摘要只包含以下有界信息：

- `toolCallId`、`toolName`、来源提供的关联身份及排序锚点；
- 标准执行阶段、已确认的 `isError`，以及可选退出码和计时；
- 确定性 `inputSummary`、`resultSummary`、`errorSummary`；
- 各内容部分的 locator、格式及是否具备读取能力；当前字节数和可用性可以未知。

字段由 Protocol `tool-activity.ts` 的 strict schema 定义。摘要字符串按 UTF-8 预算截取并明确标示省略；完整结构化参数从不通过“截成不合法 JSON”产生摘要。操作对象、文件数量等由 adapter 读取已知原生字段，未知工具使用通用名称和状态，不新增模型调用来生成摘要。

消息中的 `tool_call` 只携带关联引用和必要的小摘要，不再重复整个参数对象。历史工具结果的常规投影也只保留摘要和内容引用；不能只缩 live，然后在完成后的 history、catchup 或 displayEntries 中重新发送原文。

历史表示必须由最终原生事实确定性生成。随机读取 token、缓存过期时间、接收时间、累计收包次数和当前临时文件路径不得写进不可变 Entry；这些属于当前可用性或读取响应。相同输入和投影版本必须生成相同历史摘要与 locator。

### §4 完整内容的来源与生命周期

内容 locator 指向工具身份及内容部分，例如 `arguments`、`output`、`result`。它不是任意文件路径，也不等于保证原文永久可用。adapter 必须区分“来源没有该部分”“尚未生成”“可读取”“临时不可用”和“已不可恢复”。

1. 已落盘内容优先由 adapter 查询原生持久历史，Host 提供统一读取入口和有界页缓存，不导入全量历史形成第二份永久工具数据库。
2. 运行中内容由 producer 保存到有界临时存储。Codex 输出增量、Pi 部分结果或 DSH stream 的采集只写内容存储和摘要修订，不复制进每份共享状态。存储索引进入统一模型，原始内容不进入 Registry 单值。
3. Pi producer 在扩展侧保留无法由 SessionManager 重取的 live 内容，并通过可关联的范围读取服务 Host；不能先把全文推过 loopback 再丢掉。Codex/DSH 即使运行在 Host 进程，也遵守同一适配接口。
4. 工具完成后核对原生最终结果，再使 locator 指向已确认的来源。没有证明 live 输出与最终结果字节一致时，不拼接成一个虚假的完整文本；分开表示可保留的执行输出和最终结果。
5. 来源仅支持整条 RPC 时，adapter 可以做有界、可取消的读取及短期复用，不能声称已支持原生范围读取。并发、响应体上限和重复拉取成本必须测量；超预算返回明确不可用原因。
6. Host/producer 重启、临时数据淘汰或原生历史不含该内容时，返回 `content_expired` / `content_unavailable` 或已保留的明确范围。不返回空字符串伪装成完整结果，也不保证上游已经截掉的数据能被找回。

临时文件必须有配置化的单工具字节上限、producer 总字节上限、保留时间和淘汰顺序；每项都须在实现 PR 固定数值并做压力验收。达到单项或总量限制时停止保留新原文或淘汰允许淘汰的范围，记录确切缺口，不能无限写磁盘或阻塞原生工具执行。正在读取的页使用有界固定版本保留，无法保留时明确使读取失效。

首批实现采用以下默认值（均可配置）：单内容部分 16 MiB、同工具全部部分合计 16 MiB、producer 64 MiB/256 个部分、最后一次生产更新后保留 10 分钟；读取租约 30 秒、最多 64 个读取身份/256 个请求关联记录；内部待写原文 1 MiB/64 项、单次写入最多 1 MiB。总量或条目数达到上限时优先淘汰已结束内容，再按最后生产更新时间从旧到新淘汰；当前部分超限只保留连续前缀，记录所有未保留的后缀坐标。adapter 必须将大输入拆成完整 Unicode 边界的有界写入，队列 busy 后重试或明确记录来源缺口。

临时目录按 producer 身份隔离并使用排他锁；同一 producer 重启时只清理自身目录，不扫描删除其他 producer 的文件。`createProcessToolContentStore` 只有在操作系统返回旧 PID 不存在（ESRCH）时回收自身锁；未知权限状态不回收。Host 与 Pi producer 均使用该入口。

Codex 的 `aggregatedOutput`、其他输出字段和 MCP structured result 都必须在 adapter 的来源测试中覆盖。二进制和图片仍按 ADR-0034 使用引用，不把 base64 序列化成文本页。

Codex 历史详情读取首批采用 full turns 整页 RPC，按最近 turn 向前查找已确认工具；单原生响应完整 JSON 32 MiB、一次查找累计 64 MiB/64 页、单 RPC 15 秒、整个查找 30 秒，均可配置。同一 producer 只准入一个昂贵原生查找，其他请求返回 busy；同一内容版本后续页复用有界存储，不重复从原生获取全文。Host 共享一个 producer 存储给多 Session，runtime 最多保留 32 个原生 reader；读者结束不删除 Host 仍拥有的共享存储。

这里的响应预算在本地收帧、JSON 解析后检查，并非 Codex 上游传输帧的内存上限；原生 RPC 本身仍一次返回整页。取消结束本地等待并使迟到响应失效，不向原生发送中断工具命令。原生字段过深、结构无法表示、分页重复或扫描超预算时明确返回不可读取，不使用占位文本伪造完整详情。

### §5 工具库存也有界，完整性不能靠静默删除维护

把每项改小只能约束单项；长轮次、并行工具和等待前序提交的已完成工具仍可能增加库存数量。因此工具摘要库存与完整原文分别分页。

当前工具库存只包括执行中及已结束但尚未转入历史的工具。已提交工具通过有界历史页及其摘要引用取得，不把整份历史工具集合保留在当前库存里。

- checkpoint 只携带固定版本的工具库存引用（`live.toolInventory`），`live.tools` 为空；摘要通过 `session.tools.open/read` 取得固定快照页，包含总量、分页 cursor 和覆盖声明，不截取数组后继续宣称库存完整。
- 后续页固定同一来源版本和库存 revision；新工具或状态变化不改变正在读取的页。App 在取得完整库存前保留旧已确认库存并标记更新中，只有完整接受的新基线或明确 remove 事务才按缺席删除工具。
- 分页期间后续工具变更有界缓冲，基线应用后按连续 revision 回放；缓冲超限就废弃这次读取并重新获取当前基线，不能混合不同版本后标为完整。
- 稳定基线之后使用工具摘要 upsert/remove 增量；正文输出新增字节本身不导致完整工具库存重发。字段未变不产生摘要 revision，当前字节数等进度字段按合并窗口发布，不逐字节增加聊天 source seq。
- 工具域可以独立恢复；聊天 checkpoint 引用所依赖的工具库存版本。App 可以先显示已验证的正文及工具占位，但在依赖缺失时不推进完整聊天 applied 基线；也不能让详情读取成为聊天基线的依赖。

这要求修改当前 `SessionLiveState.tools` 直接携带完整数组的契约；不是在现有 `session.patch` 外面任意切几片。新的工具域 revision 与聊天 `source.epoch/seq` 分别定义，跨域依赖由来源事务确认，不从传输 sequence 推算。Registry 按有界库存页或有界分域记录存储，不将原始内容或全部工具库存重新拼成一个无限单值。

新协议明确：live 的完整性表示应显示消息及工具引用的可恢复覆盖；完整原始参数和输出通过 locator 单独读取，不再是 `live.complete` 的前提。这是对 ADR-0024、ADR-0032 工具载荷范围的显式调整。

库存基础实现固定以下可配置上限：256 个会话，单会话 4096 个摘要/8 MiB，全 Host 16384 个摘要/32 MiB；库存原文不计入这些预算，因为禁止原文进入库存。固定快照最多 32 份、摘要累计 16 MiB、租约 30 秒，到期、设备断开、会话结束或模型重建时释放。接收端单会话最多 4096 项/8 MiB，分页期间最多缓冲 64 个增量/1 MiB，超过任一限制重新请求基线并保留上次已确认库存。来源与接收端各保留最多 64 个 retired epoch；不靠遗忘旧代次接受迟到数据。

大于 128 项或完整 JSON 超出 60 KiB 的单次原子工具变更发出 `session.tools.changed`，要求重新读取固定版本基线，不截断 upsert/remove。聊天依赖校验要求库存版本及其确认来源版本准确匹配；库存移除已经生效后，不能用较新库存证明旧聊天 checkpoint 的工具引用仍然完整。Host 的 prepared Registry commit 和 App 的库存依赖队列协调跨域应用，详情内容不参与这一依赖。

### §6 详情读取按设备、内容版本与范围关联

统一工具内容读取操作为 `session.tool.content.read`。请求关联 `requestId`、Runtime 路由、Session、工具 locator、内容部分、读取版本及范围。首次读取固定当前内容版本；后续请求携带服务端返回的固定读取身份。响应只回请求设备，不广播到其他设备或写回共享 live。

读取必须满足：

1. Host 先验证已配对设备、Session 与 locator 的归属，再交 adapter 查询；客户端提供的 locator 不获得跨会话或任意路径的额外权限。
2. 返回 `contentEpoch`、固定 `readId`、内容格式、已读取范围、`nextCursor`、可用字节边界、是否最终结束和缺口信息。未知总长度不伪造为 0。
3. 字节坐标采用 UTF-8 原文坐标，页边界须完整覆盖字符；客户端使用返回的 next cursor，不自行用字符数推导下一个字节 offset。
4. 运行中仅追加输出可保持同一 `contentEpoch`，一次读取固定 `throughOffset`。读取固定范围不因后续追加就全部失效，也不能在重试时偷偷返回新范围。
5. 输出替换、内容修正或重建无法证明等价时更换 `contentEpoch`。旧读取明确返回版本失效；App 不把新旧内容拼接。内容版本不等于每次聊天 source seq。
6. 参数和结果是结构化 JSON 时，定义确定性序列化表示及格式；分页可以是该表示的 UTF-8 文本片段。片段不得冒充可独立解析的完整 JSON；完整读取和校验后才能执行结构化展示。
7. 到达当前输出末尾与工具最终结束分开表示。工具仍运行时显示“已到当前末尾”，不得据此标为已完成。缺口不能靠后续有数据掩盖。
8. 重复读取同一有效身份与范围幂等；有上限的请求记录、超时、取消、重试及退避。背压是可重试 busy，不修改聊天 source 的成功状态或运行态。

### §7 用户打开详情后才跟随输出

默认模式没有工具原文订阅。打开详情触发首屏读取，滚动加载旧内容；“跟随输出”由用户显式启用，优先从当前末尾读取新增范围，停止跟随后不继续后台下载。复制全部或导出也属于显式读取操作，要有进度和取消。

跟随采用单设备、单查看器、同一内容身份的有界范围请求或长轮询；无新内容不重传整个前缀。切换会话、关闭详情、App 进入后台或连接归属改变时停止调度，服务端读取也有租约清理。取消详情读取不会停止工具或取消其他设备的查看器。

已读取内容是 AppLocalState 的独立有界缓存，不参与 Session Tree Cache 的祖先 coverage、head、source seq 或快照 applied 判定。离线时可读已缓存部分，明确显示缓存范围与是否完整。

首批 App 查看器缓存上限 2 MiB；超限可清空已读文本后继续。导出使用系统文档创建器显式创建文件，逐页写入当前固定读取范围，不在内存拼接全文；上限 64 MiB，有字节进度和取消。存在缺口或取消时删除本次未完成的导出文件，关闭详情和进入后台也取消导出。导出当前范围不表示运行中的工具已结束。

### §8 初始传输预算与背压

以下为首批实现参数；协议、producer、Host 与 App 各自执行对应预算。

| 项目 | 上限或规则 |
| --- | --- |
| 单工具摘要的完整 JSON UTF-8 大小 | 4 KiB，含关联字段；超长身份不得直接截断冒充原 ID |
| checkpoint/patch 中的工具数据 | 只带库存引用，摘要单独分页；不内联完整工具数组 |
| 单份工具库存页或原子增量 | 128 项且业务 JSON 不超过 60 KiB；完整运行时响应不超过 64 KiB |
| 单详情响应 | 业务 JSON 不超过 60 KiB，完整响应 64 KiB，含转义和元数据；App 请求原文上限 32 KiB |
| 每设备详情读取并发 | 2；单查看器最多一个在途范围请求 |
| 详情响应等待发送字节 | 每设备 256 KiB，采用保守的密文及分片封装估算；封帧前准入 |
| 当前摘要/输出通知 | 复用来源合并窗口；字段不变不增加库存 revision，输出字节追加不推进聊天 source seq |

内容读取与聊天同步分别记账；网络发送仍服从现有总队列和路径背压，详情不得占用全部控制面或让聊天恢复持续饥饿。大量内容导出优先复用范围下载的数据传输机制；不能把兆字节结果塞回 `command.result` 或 `ctl`。已封装帧的处理继续遵守 ADR-0007、ADR-0010、ADR-0044。

4 KiB 摘要上限并不意味着 256 项可以直接一起发。必须同时满足累计预算和完整 envelope 预算，嵌套 JSON 转义、displayEntries、工具引用及包装开销均计入。身份本身超预算时明确拒绝并报告不可表示原因，不能省略该项后宣称完整。

### §9 live 转历史仍是一笔来源事务

本决定不删除 Codex 的有序提交规则，也不提前把未完成工具写成最终历史。

- 工具执行结束、正式历史确认和原始内容可读取是三个独立事实。已完成但等待前序 item 的工具保留摘要及可用 locator，不保留重复的大结果正文。
- 对应历史摘要 Entry、显示引用、head 和 live 移除必须保持原子关联。依赖的工具域 revision 在同一来源事务发布，App 不在中间状态重复显示或漏掉工具。
- live locator 转到持久来源后，逻辑工具身份不变；已有详情读取只有在内容可证明同版本时继续，否则明确重新读取。
- 历史分页和详情分页都不移动当前 head、不清 live、不结束工具。原始内容不能通过日志文字、读取结束或请求失败反向改变工具状态。

### §10 投影版本与旧缓存迁移

历史工具 Entry 从完整内容变成摘要/引用会改变同 ID 的 `data`，不能只更换 UI，也不能依靠“同 ID 忽略新内容”保留旧缓存。

协议硬版本升级到 15，显示投影版本为 3，工具摘要投影版本为 1；按 ADR-0025 建立明确的新 source epoch，并在 App 一笔事务内使受影响 Session 的旧 canonical/display 缓存、cursor 和 coverage 失效后写入新有界基线。先前下载的工具原文不能混入新历史投影。

保留配对、设备身份、草稿和其他用户本地配置；迁移失败回滚，不要求卸载或清 App 数据。不支持新旧工具业务格式同时驱动状态，也不保留旧 `tool.updated/finished` 携带全文的旁路。

### §11 与既有决定的关系及范围

| 既有决定 | 本提案采纳后调整与保留 |
| --- | --- |
| ADR-0024 | 调整“完整 live”的工具载荷含义：完整摘要/引用覆盖即可，原文独立读取；保留完成未提交内容的可恢复身份及提交原子性 |
| ADR-0025 | 保留原生权威、确定性投影、epoch 握手及缓存事务；新增投影迁移验收 |
| ADR-0032 §4/§5 | 工具输入、部分输出和结果可由模型引用及统一读取表示，不要求 Registry 内联全文；保留 Host 唯一入口、adapter 解释原生事实及 App 通用展示 |
| ADR-0034 | 保留媒体只传引用，二进制不进入摘要或文本内容页 |
| ADR-0038 | 工具路径由摘要+引用替代默认传全文再截断；助手正文/思考等文本仍按原有规则处理，现有全文 Entry 请求不能作为工具大内容分页实现 |
| ADR-0035 / ADR-0044 | 保留合并、变更信号和队列预算；工具正文的追加不再要求重发完整聊天 live |
| ADR-0005 / ADR-0013 / ADR-0037 | 复用接收方驱动、明确范围/归属、资源预算和租约原则；详情读取不冒充聊天同步事务，不推进聊天 applied |

本地代码已按本决定替换工具运行路径，其他 ADR 的未调整机制继续生效。实施记录区分本地合成来源、设备链路与真实外部后端验收；本地完成不代表生产环境已升级。

超长助手正文、思考正文和非工具 live 库存仍可能超预算。本 ADR 不宣称消除所有 `session_metadata_too_large`；其分页或内容引用需要独立设计，不能继续以省略正文数组但声称完整的方式处理。

## Consequences

- 默认工具同步大小由摘要与引用数量决定，不再随工具输出的累计字节增长；详情开启时仍会消耗与实际读取内容相应的带宽。
- App 日常聊天以正文和工具执行摘要为主；查看原始输出多一次显式操作和读取延迟，离线只能查看已缓存部分。
- Host/producer 增加内容索引、临时存储、范围读取、库存分页和版本管理成本，但不新增无限期的全量聊天数据库。
- 原生内容缺失、上游截断和临时存储淘汰仍可能使全文不可恢复；必须可见，不能用缓存策略承诺没有来源保证的完整性。
- 历史投影和协议需要协调升级；文档、单测或本地构建完成不表示已更新用户正在运行的 Host/App。

## Implementation and verification

实施顺序：先定义 schema、内容身份/版本、预算及迁移；再实现统一 adapter 内容接口和摘要生成；接入 Host 模型与有界读取；最后实现 App 工具活动、详情与缓存，并协调切换协议。不得只改 App 外观后宣布解决带宽问题。

必须覆盖以下验收，结果分别记录为模拟测试、真实后端测试和设备测试：

1. Codex、codexDesktop、Pi、DSH 的正常、失败、取消及未知工具使用同一显示契约；新增后端不需要 App 解释原生 JSON。
2. 单工具产生 10 MiB 输出、大型结构化参数和含媒体的 MCP 结果时，默认 patch/snapshot/历史页/loopback/Registry 中没有完整原文、base64 或双份参数；工具字段满足单项、累计及 envelope 预算。
3. 复现前序未完成、后续 8 个及大量工具完成的情况：摘要可恢复且顺序正确，库存超单页时分页，不伪造完整、不漏工具；前序提交后历史与 live 原子切换。
4. 用户不打开详情时没有原文范围请求；打开后只读请求范围，关闭、后台、切换或断线后停止；其他设备不收到详情，工具执行不受查看器取消影响。
5. UTF-8 多字节、JSON 转义、超长单行、多字段 JSON 和二进制引用均满足实际 JSON 字节预算；结构化片段不被错误解析成完整 JSON。
6. 固定版本读取遇到持续追加、最终结果替换、revert、Host/producer 重启、缓存淘汰和原生缺内容时，不混版拼接、不返回假空成功；缺口和失效明确。
7. Pi 的消息结束早于落盘、DSH 的流式结束早于 canonical event、Codex 的工具乱序结束及 `aggregatedOutput` 均有真实形状 fixture；来源不支持按需全文时准确标明能力。
8. 故意丢工具增量、延迟库存页、分页期间持续变化和缓冲溢出后，基线可恢复；详情错误不污染聊天 head、coverage、source seq 或 applied。
9. 两设备同时查看、慢链路、停止读取、大结果导出及 busy 重试时，发送队列、临时磁盘和缓存占用均有界，聊天、审批和停止命令仍可处理。
10. 旧缓存升级在事务失败与 App 重启后可恢复，不清配对数据；相同原生输入生成相同摘要、locator 和历史投影，不将临时读取身份写进 canonical Entry。
11. 诊断记录按作用域分别统计摘要/正文/详情的实际字节、请求数、缓存命中、缺口、队列和存储上限命中；只记录身份和计数，不记录工具原文。以同一输入序列对比重构前后实际传输量，不从单一峰值推算固定节省比例。

真实 Host/App 联动使用隔离 Host 测试台；用户当前 Host 的更新、停止或重启，以及 push、发版、部署分别遵守仓库授权约束。
