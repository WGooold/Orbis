# ADR-0046：移动端的阅读位置、材质和动效统一约束

日期：2026-10-29

Status: accepted

关联：[ADR-0039](0039-content-change-signals.md)、[ADR-0041](0041-history-paging-edge-trigger.md)、[ADR-0042](0042-bounded-shadow-bitmaps.md)

## Context

`ui-polish` 工作树原先只有未提交的 iOS 界面改动，没有本轮的 ADR；Android 尚未实现。
本记录把原任务的 17 条要求落实为两端共用的界面约束。它补充现有协议和状态决策，
并取代历史 UI 文档中与本记录冲突的字号、圆角和嵌套材质规则。

长回复不能用「最后一个列表项仍可见」推断用户正在看末尾：一个助手轮次本身就可能跨越几十屏。
发送、刷新、后台同步和输入聚焦也不能各自拥有一套追新策略。
同一张卡片里逐层加阴影、加载时插入提示行、状态文案改变宽度，会放大流式更新带来的视觉抖动。

## Decision

### 1. 聊天只有一个跟随规则

- 用视口与内容末尾之间的实际距离判断；小于一行时可恢复跟随。
- 用户开始拖动立即停止跟随，惯性滚动结束前保持停止。Android 同时处理滚轮 / 触控板的 UserInput。
- 离末尾超过三行时显示「回到最新」；只有点击该按钮才显式跳转并恢复跟随。
- 新打开会话以跟随状态开始；发送、输入聚焦、刷新及同会话分支动作不会另外要求追新。
- 分页补入前缀和同步临时清空投影时，可以校正原有消息 key / offset，使正在阅读的文字留在原坐标；这不是跳到最新。
- 非跟随即进入阅读位置锁定：底部追加消息、工具卡片和流式文本不能移动现有阅读锚点。锁定的是内容相对视口的位置，不是禁止用户滚动。
- 拖动和惯性期间，原生列表继续按当前消息身份与行内偏移维护锚点，用户位移正常生效；后台刷新或补页不得重放用户移动前保存的位置。停稳后锁定新位置，只有用户滚回一行内或点击「回到最新」才恢复跟随，内容变短或暂时清空不能自行恢复跟随。
- 不修改 ADR-0041 的分页边沿触发规则，不因滚动位置轮询而连续下载历史。

iOS 使用 `scrollTargetLayout` 注册稳定消息身份，18 及以上由原生 `ScrollPosition` 同时管理用户滚动、阅读锚点和显式回到底部，17 使用 `scrollPosition(id:)`。非跟随时不设置尺寸变化的默认边缘锚点；补页不再用旧 ID 的 `scrollTo(.top)` 覆盖用户的当前行内偏移。18 及以上使用原生滚动几何和 phase；17 从原生 pan 观察到减速结束。
Android 使用 LazyList 的像素几何、稳定 key、拖动状态和嵌套滚动来源，移除旧的按列表项数量追新判断。手势与惯性消费的位移推进本地代次，使旧的刷新 / 补页恢复请求失效；需要校正时同时核对消息身份和像素偏移。

### 2. 同一块内容只有一个材质外框

- 最外层独立卡片 / 面板使用原有双向柔影；后代通过环境里的层级和深度改成平铺明度层。
- 浅色四层依次为 `#DDE3EF / #E6EBF4 / #EDF1F8 / #F3F6FB`；深色为 `#1C1F26 / #23262E / #292D36 / #2F333D`。
  相邻层的 HSL 明度约差 1–3%。应用绘制的遮罩和投影使用带色墨色，不使用纯黑。
- 子表面的圆角继承父圆角减内容内距；圆形按钮和胶囊保留自身几何。
  通过 `contentPadding` 或 `contentInset` 声明内距，不能让外部 padding 与材质环境失配。
- Markdown 表格用行底色区分，取消逐格描边；代码、引用、工具和按钮不再叠第二层柔影框。
- 输入聚焦加深凹槽，用柔和的双环强调色提示，不用黑色硬描边。
- Android 保留 ADR-0042 的有界九宫格阴影缓存；嵌套平铺面不生成阴影图集。

2026-10-29 补充：独立操作可与所属卡片并排放在页面底板上。侧边图标按钮使用 36pt / dp 可见圆面、
18pt / dp 图标、48pt / dp 触控区与更浅的阴影；卡片与触控区直接相邻，利用圆面外侧的 6pt / dp 留白
形成可见间距，不再额外叠加 12pt / dp。适用于会话别名、目录新建 / 会话菜单和下载取消 / 重试 / 分享。
供应商操作预留等宽位置，避免有无操作时卡片右边缘参差；连接排序保留连续文字行与并排小按钮，
不为每行静态说明再增加独立凸起卡片。
以阅读宽度和操作关联为准，不批量外移所有子控件：正文 / 代码复制、通知关闭、表单选项和弹窗操作
继续就近放置，并遵守已有嵌套材质规则。不能通过清空材质环境，在同一张卡片里强行叠第二层阴影。

### 3. 字体、文件名和稳定的反馈槽

- 界面文字只有 `20 / 15 / 13 / 12` 四档，最小 12；层级优先用字重、颜色和间距。
  图形大小不计入文字档位。数字统一等宽。
- 文件名把主名与最后一个扩展名分开布局，只对主名尾部省略；点文件和尾随点不算扩展名。
- 状态、转圈、待确认和短反馈在保留的槽位中替换；审批覆盖面板和短反馈不插入聊天消息行。
- 聊天顶栏的刷新转圈复用行首状态图标的固定槽位，不追加到模型名后；刷新前后状态、模型和思考级别的文字宽度与省略位置保持不变，状态文字保持单行。
  Android 顶部的错误短文留在原槽，点击可打开错误详情与重试；分页失败不自动重试的语义不变。
  用户主动展开、输入换行及系统键盘改变视口仍属于正常布局变化。
- 删除 UI 自己生成的中点分隔符和重复操作说明；不改写 Host / Agent 发来的正文。
- Android 正文使用原生 Paragraph 断行；iOS 使用系统文本断行，不用人为插入空格或换行模仿 CSS。
- 文字旁的图标做 0.125em 光学校正；iOS 按首行基线实现，独立图标按钮保持居中。

### 4. 动画只改变呈现，不重建内容身份

- 折叠先测量完整内容，再把裁切高度从 0 插值到自然高度，等价于 Grid 的 0fr → 1fr；保留草稿和展开状态。
  Android 目录保留 LazyColumn，折叠最近的有界预览行，不把整个目录转换成非虚拟化 Column。
- 自定义拖拽回位使用质量 1、刚度 1200、阻尼 80；勾选反馈使用 380 / 18。
  原生系统抽屉、键盘和模态手势由平台控制。
- 复制成功的对勾 2.5 秒后恢复；重复复制重置计时。失败状态不按成功反馈自动消失。
- 只给新增流式字形做 6pt/dp 模糊渐显，单字 120ms，字间错开 30ms。
  大批量到达时将等待压到 450ms 以内，避免全文排队几分钟；Android 每次最多保留末尾 128 个活动字素。
  历史文字、既有字形及布局尺寸不参与动画。
- iOS 18 使用 TextRenderer；iOS 17 直接显示文字。Android 保留原生 Text 的测量、选择和链接语义，
  仅在绘制阶段处理新字素，并复用有限组模糊画笔。两端尊重系统减少 / 关闭动画设置。

## Verification

- iOS：61 项核心测试、模拟器 Debug 构建、12 项 UI 测试全部通过，包含长末尾回复的滚动和审批提交时输入框不位移。
  9 个页面的浅色 / 深色截图已导出核对，另有阅读锚点和恢复跟随截图。
- Android：477 项单元测试、Debug / AndroidTest 构建及专用 Android 35 模拟器上的 19 项设备用例通过，
  覆盖滚动、Markdown、审批、目录筛选、文件浏览、明暗外观和图形内存有界回归。
  逐项记录见[移动端 UI 打磨验收](../testing/mobile-ui-polish.md)。
- 所有界面夹具都使用内存数据或测试自己的命名空间；未连接生产 Host，未操作用户手机。
- 本机 Android 37 预览系统与仓库的 Espresso 输入接口不兼容，不能把该环境的异常算作产品回归结论；
  验收改用单独创建的 API 35 模拟器。
- 合入主分支后，172 项 iOS 核心测试和 478 项 Android 单元测试通过，15 项不同 iOS UI 用例已有通过结果；
  新版来源事件夹具的兼容修复、定向复核和结果包索引见上述验收文档的「合入主分支的回归」。

## Consequences

新页面须使用共用字号、输入、材质和折叠组件。新增卡片嵌套时必须传递内容内距，不能通过叠加阴影补层次。
UI 状态更新不改变消息 key、会话身份或协议事实；历史位置校正只维持原来的阅读锚点。
模糊渐显是可降级的绘制效果，不是消息完成或同步完成的证据。
