预跑错误全部保留在 `.artifacts/quic-diagnostics/preflight-summary.json`：首次回环 TLS 触及 1 GiB 护栏；一次公网准备遇到容器 metadata 目录权限错误；qlog value-event 适配遗漏由真实连接检查发现后修复。它们不混入正式性能样本，旧 cleanup-required 有后续独立释放审计，不改写为初次成功。

性能测量结束后，固定候选的完整 Go race 回归含真实 Node 夹具与连续字节夹具共 **52 个测试事件通过、0 失败、0 跳过**；事件计数含子用例 / fuzz seeds，不冒充 52 项原生手机功能。Python 聚合 8 项、Node 夹具语法检查通过。证据 `.artifacts/quic-diagnostics/final-go-race.jsonl`、`final-go-race-summary.json`；构建 / 验证租约最终释放并再次检查共享队列。

### 可以得到什么结论

1. **控制延迟改善跨负载重复出现。** 原负载下载 p95 从 WSS 的 4.345 秒降至 QUIC 的 0.464 秒；原负载上传从 1.302 秒降至 0.499 秒。流水线下载 / 上传 QUIC p95 均约 0.47–0.48 秒，WSS 分别约 5.53 / 9.00 秒。本轮各场景 p95 中位数降低约 62%–95%；这是三流、调度和传输整体结果，没有单独禁用 priority 的因果对照。
2. **吞吐优势不统一。** 原负载 QUIC 下载约 15.10 Mbit/s，高于 WSS 的 8.81；上传约 1.68，低于 WSS 的 7.55。小块流水线 QUIC 上传三轮为约 3.98、21.70、1.21 Mbit/s，没有稳定提升；其下载中位数也低于 QUIC 原负载。不能据此把单块 ACK、JSON 或 64 KiB 发送水位认定为唯一瓶颈，也没有证据支持直接切换整个产品到流水线策略。
3. **此前 0.14–0.28 Mbit/s 不是协议实现的固定带宽上限。** 原负载本轮下载能达到十余 Mbit/s；但预热、计量时长与先前 60 秒试验不同，网络也变化。**20 秒全过不能作为先前 60 秒排空 / 断链失败已经修复的证明**，原失败继续保留。
4. **原始传输与业务层都存在需要归因的因素。** D1 原始 NewReno 已显著波动；D2/D3 又观察到确属测试 socket 的接收丢包、CPU quota 和应用写入等待。当前不能通过单段 / 双段吞吐相除确定各项开销，也不能宣称换成 BBR 一定解决。

### 已定位的接收条件与本地等待

- 独立 UDP/24443 socket inode **4897174**，由测试容器 Go 入口 PID **297806** 的 fd 6 持有，归属已核对。`skmem` 接收缓冲为 **425984 字节（416 KiB）**；10:51:21 采样 drops=4920，10:59:02 同 inode drops=**8184**。它们是该 socket 的内核接收丢包计数，包含本轮所有 QUIC 会话；最后一次采样不是结束瞬间，所以全程丢包量至少为该数。不能将累计值当作某一轮线路丢包概率。
- 同容器 `cpu.max=100000 100000`（1 CPU quota）。晚期采样 `nr_throttled=220`、`throttled_usec=6458468`，即累计约 **6.46 秒** throttling；离散 CPU 采样峰值 **98.62%**。存在执行受限条件，但累计值不证明每次丢包由 CPU quota 触发；缺少逐包 / 调度时间关联。
- 48 个 QUIC endpoint trace 均有有效 metrics / packet 事件；48 份最终 writer 统计保留三 lane 的字节和 Write 时长。客户端 / helper 的 bulk 单次本地 Write 最长约 **368.93 ms**，Relay 约 **251.93 ms**。这些是本地提交等待，不是公网交付时间，也不能据最大值反推持续吞吐。
- Host 进度中可见 bulk 队列与约 64 KiB 本地待写量；Relay writer 的采样队列、各 lane 接收帧字节与每秒 verified goodput 均保存。它们证实存在应用准入 / 排队，但未做单独移除或替换准入的对照，不能先删除原护栏。
- 资源采样 572 次，本任务进程合计 RSS 采样峰值 **238.56 MiB**；容器内存采样峰值 **60.27 MiB / 512 MiB**。这些不是实时最大值或长期容量验收。
- Mac 另一个工作树的 Android 动效回归从 **10:52:32 UTC** 持有共享设备，覆盖本轮上传时段；本任务没有占用或干预它。客户端不是独占性能环境，不能排除本机调度影响。

### 下一项单变量对照

优先核查接收条件：在隔离服务中分别对比同 CPU 限额下的 socket 缓冲、同缓冲下的 CPU 限额，并采集同 inode 的 drops / cwnd / flow-control 时间序列，再判断是否调整部署或 adapter；不在生产主机上临时改全局 sysctl。接收条件稳定后，再准备可维护的 Reno / BBR 候选并执行 D4。当前没有运行这些额外单变量控制，不能将上面的信号写成修复验收。
