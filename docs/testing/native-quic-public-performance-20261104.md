## 结果与判定

**Host↔Relay↔参考客户端两段公网均已测量；本次观察到 QUIC 在 bulk 并发时控制响应更可用，但没有证明 bulk 吞吐提速，性能与发布门禁未通过。**

正式测量从 **2026-11-04 08:35:19 UTC** 开始，末次资源采样为 **09:06:23 UTC**，共约 31 分钟。3 个场景 × 2 种承载 × 5 轮，**30/30 次尝试全部保留**；29 次进入测量，21 次可确认完成固定计量窗口，16 次同时无错误且完成排空。首次 WSS 下载在启动阶段失败，未确认实际 Host 承载；其余 29 次核对了两段实际承载与要求一致，QUIC 没有静默回退。`allConfiguredRoundsPresent=true`、`allAttemptsPassed=false`，进程退出码为 1，不能记为测试全过。

## 实际测了哪条链路

```text
Mac 上的真实 HostRelayClient / 原 E2eChannel / piece / OutboundChannelMux
  → 公网 WSS 或 QUIC（Host helper，Host 专用 ALPN）
  → 真正 Relay 主机 45.58.185.226 上的隔离候选服务
  → 公网 WSS 或 QUIC（device ALPN）
  → 同一 Mac 上的 Go 参考客户端 / 解密 / 校验

上传沿反方向；控制探针走客户端 → Relay → Host → Relay → 客户端。
两种对照分别为 WSS/WSS 与 QUIC/QUIC，两段实际承载都核对。
```

这是两段公网的完整传输链路。参考客户端与 Host 在同一 Mac，不是物理手机蜂窝 / Wi-Fi，也不是原生 App 或真实 Agent 推理性能。每条腿都连接远端 Relay，不用本地回环代替公网。Host 侧使用生产 helper / 分 lane IPC，Relay 使用生产 Go `ServeRoutes` / Node 认证路由；没有使用功能回归的 WS-to-QUIC 手机 API 桥。

生产入口 `orbising.com` 的 TCP 443 经过香港入口转发至这台 Relay 的 9443；原入口没有此候选 QUIC 宣告。本次直接连接真正 Relay IP 的独立 TCP/UDP 24443，同 IP、同端口和同临时 TLS 1.3 信任根；严格校验证书 IP SAN。没有更新生产 Relay、nginx、Hysteria、用户配对或账号。临时防火墙规则仅允许服务器观察到的本次测试源 IP，并随测试清除。

Mac 去 Relay IP 的路由为 `en1 → 192.168.1.1`；去香港入口 `149.62.46.30` 的路由则是 `utun4 → 198.18.0.1`，已有代理会参与。本文测前者，**没有把它说成现有香港入口或真实手机路线的性能，也没有进行同机 Hysteria 2 对照**。路由原始记录位于 `.artifacts/quic-review/public-network-provenance.json`。

## 同条件与计量方法

| 项目 | 固定条件 |
| --- | --- |
| 客户端 / Host | Apple M6、16 GiB、Darwin arm64；Node 22.23.2、Go 1.27.3、quic-go 0.65.0 |
| Relay | Linux 6.8.0-57 x86_64、主机 2 vCPU；独立只读容器限 1 CPU / 512 MiB，Node 22.23.3；JS 为本工作树候选 |
| 网络 | 原公网线路，IPv4；未人为注入延迟 / 丢包 / 限速，其他公网流量不受本测试控制 |
| 协议 | WSS 不压缩；QUIC 使用同连接 ctl/msg/bulk 三条流，生产 Go 原生优先级；强制 QUIC 禁止回退 |
| 数据 | 1 MiB 随机块，前 8 字节为递增序号；AEAD、原 8 KiB ciphertext 分片；逐块核对序号和全部内容 |
| 窗口 | 下载固定 4 MiB 在途；上传一块在途；固定夹具窗口，不冒充 App 自适应文件窗口 |
| 样本 | idle / download / upload，每种协议各 5 轮；奇数轮 WSS→QUIC，偶数轮 QUIC→WSS |
| 时段 | idle 预热 2 秒 / 测量 10 秒；上下行预热 10 秒 / 测量 60 秒；统一 60 秒结束排空预算 |
| 控制 | 每 100 ms 一次加密 ctl 往返；从计划发出到收到并解密回声，包含本地排队时间 |

下载吞吐仅计固定测量窗口内已经解密并校验的完整块有效字节；上传按同窗口内收到 Host 校验 ACK 的块计数。排除 8 字节块头、AEAD、base64、JSON 和传输开销。Mbit/s 为十进制；MB/s = Mbit/s ÷ 8。预热和排空期间完成的块不计入吞吐。1 MiB 粒度在 60 秒窗口下约为 0.14 Mbit/s，慢链路的单轮读数因此有明显量化误差。

预置一次性方向密钥以隔离稳态传输，不测配对 / E2E 握手，也没有 HostService 文件读写、手机 SQLite、真实文件落盘或 UI。实际功能另由四种传输组合的 HostService 回归验证；性能夹具不能替代它。

p50/p95/p99 先对每轮使用 nearest-rank，再取轮次分位数的中位数。未回复 / 未发出的计划探针保留并按“未完成”排在所有有限 RTT 之后；命中该部分的分位数记为不可得，不丢掉慢样本。建连前失败单独列出，不伪造 RTT 或零吞吐。吞吐中位数只使用可确认完成整个固定窗口的轮次，**包含随后排空失败的轮次**；连接失败仍完整列入失败和逐轮表。原始夹具没有独立的窗口完成标记，聚合保守地只接受无错误或错误明确发生在排空阶段的记录；`host.offline` / 连接重置等阶段不明确的记录不纳入，因此完整窗口数是可确认的下限。聚合脚本有 5 项专项验证缺失探针、失败轮次和不完整窗口的处理。

## 失败、限制与解释边界

- 早期公网短跑使用原 1 秒 Host 发现预算，复现了强制 QUIC 的 HTTPS 发现超时。已先修订 ADR，再将产品显式 QUIC 的发现 / 准备预算设为 3/5 秒；auto 保持 1/1.5 秒。正式报告使用修订后的产品代码，不仅给测试放宽预算。原始短跑保留在 `20261104-public-smoke` 和 `20261104-public-smoke-v2`。
- 早期夹具的 5 秒排空不足，且错误提前返回会漏存探针。本次统一采用 60 秒排空，错误路径也保存全部测量探针；原错误数据不回填成成功。60 秒排空在本次五轮 QUIC 下载中均未接收完固定 4 MiB 在途窗口，排空超时与固定窗口吞吐分别报告，不能把未收到的剩余字节当已校验。
- 首轮 WSS 下载在 Node 元数据准备阶段超时，并由父进程强制回收。同期资源采样出现约 39 秒间隔，原因未确定；该轮保留为启动 / 夹具异常，不将其全归因于 WSS 网络性能，也不加入稳态吞吐中位数。
- 本机不是独占性能环境：清理回查时共享队列仍有另一工作树从 08:33 UTC 开始持有的 iOS 回归任务；本次没有干预它，也没有完整系统调度采样。不能排除并行工作对时间尾部的影响。
- Relay 的 `rmem_max` / `wmem_max` 为 212992 字节，quic-go 记录实际 UDP 接收缓冲只到 416 KiB。没有修改全机 sysctl；此配置、网络波动和容器限额都是本次测量条件，不能外推为协议峰值。
- 本次没有逐包丢包 / 重传归因，也未分别禁用多流或优先级做因果对照。可以报告已观察的业务响应差异，不能仅凭这些数据断言某个拥塞算法或原生优先级贡献了全部收益。
- 未完成同手机 WS / 同机 Hysteria 2 / 原生 QUIC 对照、ADR Q12 的受控快网 / 1% 丢包门槛，以及长期容量 / RSS 稳定性验收。默认 WS 保持；本报告不是生产上线通过单。

后续[成熟项目对照与诊断](../architecture/native-quic-peer-project-review.md)补充：0.139809 Mbit/s 恰为 60 秒内完成一个 1 MiB 块的计量粒度，不是线路峰值；拥塞算法、流控与 adapter 的影响尚未由连续字节基线 / qlog 分开。该复核不改写本文任何原始结果或失败，也不将推测记为已证明的低吞吐原因。

新的[分层方案](native-quic-layered-diagnostics.md)及[结果](native-quic-layered-results-20261104.md)完成连续原始字节与双段交错负载诊断，发现测试 socket 的接收丢包和 CPU quota 条件。新测量窗口为 20 秒，预热也不同，不覆盖本文 60 秒失败或宣称原问题已经修复。

## 原功能回归与复跑

本机四种 Host/手机承载组合各 **104/104**，其中 HostService 为 60 项；Node 默认全套 **1727 通过 / 0 失败 / 5 原跳过**；Go race 含真实 Node **45 个测试事件通过**。打包后的 Host 按默认相对路径使用包内 helper，QUIC→WS→QUIC 通过。原生移动端与同设备基点对照的历史结果、既有失败和未验收门禁分别见[功能报告](native-quic-functional-regression.md)，不将 Node / Go 数量相加成完整手机 UI 通过。

运行器使用预编译产物，先按本机内存 / 构建规则完成 `npm run build`、本机 `testdata/perf`、Linux `testdata/perf-server` 和 `scripts/build-host-quic.mjs`。使用已有 SSH 密钥、固定既有 Node 镜像和全新输出目录运行：

```sh
python3 scripts/run-native-quic-public-perf.py \
  --relay-ssh root@45.58.185.226 --key /absolute/path/to/existing-key \
  --public-ip 45.58.185.226 \
  --image sha256:622e53ef1f2e11ea3971e694953c8758aacc671ca278694b194898faff22ecbc \
  --output .artifacts/quic-perf/new-public-run --node /absolute/path/to/node \
  --rounds 5 --warmup 10s --duration 60s --idle-duration 10s --drain 60s
python3 scripts/summarize-native-quic-perf.py .artifacts/quic-perf/new-public-run
```

正式证据 `.artifacts/quic-perf/20261104-public-full-chain/`：`raw.jsonl` 保存全部原始探针，`run.log` 保存轮次及错误，`resources.jsonl` 保存本任务进程与隔离容器采样，`provenance.json` 保存两端候选哈希，`server.json` 保存服务器运行时，`summary.json` 保存失败感知聚合，`cleanup.json` 保存独立回查结果。私密临时配置在结束时删除，不进入报告或源码。
