# 原生 QUIC 分层性能诊断方案（2026-11-04）

关联：[ADR-0065](../adr/0065-native-quic-relay-transport.md)、[成熟项目复核](../architecture/native-quic-peer-project-review.md)、[原始公网报告](native-quic-public-performance-20261104.md)。本方案在实施夹具与新测量前登记。目标是定位低吞吐发生的层次，原始失败不改写，不把本轮诊断当作 Q06/Q12 或生产发布验收。

## 0. 用户场景修订：聊天与状态同步优先

2026-11-04 用户补充：下载很少使用，主要故障是长时间收不到聊天记录、会话状态不能同步。后续诊断优先执行下述 D6；D1–D4 的吞吐结果保留为辅助证据，下载仅作并行干扰项。D6 尚未执行，不因已有控制探针通过而记为通过。

源码已确认：`HostService.channelForDeviceMessage` 将会话 / 消息事件、目录及一般模型快照归入 `msg`；单独的 execution 状态读取 / 更新可走 `ctl`。`DeviceLink.sendSessionSnapshot` 也明确使用 `msg`。当前 QUIC 只按 ctl/msg/bulk 分流，历史、live 与目录仍共用 msg 的有序流及序号域。现有 bulk 压力下 ctl RTT 改善不能证明 msg 同步停顿已经解决；也不能直接通过任意拆流重排已有密文来修复。

### D6 测试与归因

| 场景 | 必须观察的业务终点 | 对照条件 |
| --- | --- | --- |
| 无文件传输，打开短 / 长会话 | 首次有效聊天内容显示；当前 source epoch/seq 对齐；首屏不等待全量补齐 | WSS、原生 QUIC；真实手机另加经同机 Hysteria 的 WSS |
| 持续聊天与执行状态变化 | 消息连续更新、执行状态到达且应用；检查消息 seq 间隙与最长无进展时间 | 同一数据、生成节奏、Host / Relay；两段实际承载分别记录 |
| 多会话恢复、历史补页与 live 同时发生 | 当前会话 live 和状态不被后台历史永久挡住；页提交后才 ACK，内容 / 身份一致 | 固定缓存、source epoch、页数和范围；下载作为独立的附加干扰列 |
| 短时断网后恢复、半开连接、前后台及换网 | 自动重连 / 重握手后恢复目录、订阅和当前状态，无须重开 App；旧响应不能覆盖新状态 | 隔离夹具注入 1 / 3 / 10 秒中断；手机前后台 / Wi-Fi 与蜂窝另做现场验证 |
| 慢后端、msg 排队、慢解码 / SQLite、applied ACK 丢失 | 分辨后端等待、传输等待与客户端消费；事务有限终结 / 恢复，不永久 busy，不重复执行输入 | 按 ADR-0037 的既有租约、pending、ACK 和目标级失败规则注入，保留原断言 / 超时 |

每次操作关联现有 commandId/syncId、连接代次、source epoch/seq，记录：用户读取意图 / 源状态变化 → Host 受理 → 后端响应就绪 → msg 入队 / 写入 → 手机收齐并认证 → SQLite applied → 状态 / 内容显示 → ACK。只记身份、字节数和阶段，不记聊天正文或凭据。跨进程采用关联事件和本地单调耗时，不能直接相减未同步的墙钟。已有诊断尚未贯通这些阶段，补齐后才执行 D6 计量。

报告首屏耗时、状态同步耗时、最长无进展时间、超过 3 / 10 / 30 秒的停顿次数、恢复耗时及未完成操作数；这些时间档仅为诊断分桶，不改变业务超时 / 租约。从用户操作 / 源变化起计的总耗时必须保留，另按阶段归因，不能扣除后端等待后称为端到端体验。

D6 通过至少要求原业务断言全部保持，注入的故障可自动恢复、无永久 busy / 需重开 App、无重复输入或错误 applied。性能收益须由相同手机 / 路线 / 负载的交错重复样本证明，并公开失败；没有现场数据时只报告夹具覆盖。具体交互延迟目标在首轮基线后单独登记，不把既有 ctl 探针 p95 或下载 Mbit/s 转为聊天验收结果。

优先利用用户“同机 Hysteria 后稳定”的线索核对公网路径及恢复；该线索不证明拥塞算法的单独贡献，也不排除网络中断触发已有同步事务 / 消费端问题。接收丢包与 CPU quota 来自独立高负载测试容器，尚不能归因为生产聊天故障。

## 1. 假设与判定

| 假设 | 需要的证据 | 不足以成立的证据 |
| --- | --- | --- |
| 公网 / 拥塞控制限制 | 同路径原始 QUIC 已慢；持续有数据供给；发送端 RTT、cwnd、bytes-in-flight、丢失 / PTO 对应下降；区分 UDP socket drops | 仅看到业务 0.14 Mbit/s 或 CPU 不高 |
| 生产 adapter 供给 / 桥接限制 | 原始传输较快，经过生产 QUIC / IPC / Node 路由后明显下降；逐层字节与等待显示供给空档；同 IP、相近时段重复 | 仅因存在同机 WS 就归因 TCP-over-TCP |
| 原业务粒度 / 确认限制 | 持续供给诊断列更快，原 1 MiB / 单块上传 ACK / 4 MiB 下载窗口列较慢；原 E2E / 内容正确 | 仅改变超时后测试成功 |
| 某控制器有收益 | 在相同夹具、网络、供给与窗口下只改变控制器，重复轮次并记录失败 / 控制长尾 / 资源 | Hysteria 品牌对照或不同手机 / 路线的观察 |

差异门槛用于决定下一步调查：同层同协议至少 3 个有效重复窗口，中位数差异超过 20%，且不能由丢失失败轮次或网络时段变化解释。五轮作为原始传输正式诊断样本；单轮和短跑仅作定位，不报告显著性或提速倍数。没有因果证据时标记“待归因”，不为了出结论删除失败。

## 2. 测试矩阵与执行顺序

| 阶段 | 负载 / 路径 | 样本 | 指标与边界 |
| --- | --- | --- | --- |
| D0 | 本地夹具正确性：任意分段读、部分写、内容损坏、固定窗口、取消 / EOF、诊断开关 | 必要自动测试 + 本地短跑 | 连续字节计数正确；错误和不完整窗口保留；任务退出可核验；不把回环计为公网 |
| D1 | Mac↔真正 Relay 的原始 TLS / 原始 QUIC，单段连续流；两者同 IP / TCP 或 UDP 同端口、同证书、同数据校验 | 双向 × 2 协议 × 5 轮；预热 3 秒、固定测量 20 秒；交错协议顺序 | 接收端连续有效字节 / 秒；每秒时间序列；QUIC RTT / cwnd / loss / PTO / flight / flow control；不含 Node / E2E / 应用 ACK |
| D2 | Mac Host→真正 Relay→Mac 参考端，两段真实生产承载；固定较小块、持续有界供给的诊断列 | 先每协议 / 方向 1 轮短跑，通过后每格至少 3 轮 × 20 秒 | adapter / helper / IPC / Node 路由真实参与；明确诊断负载与原 App 的差异；记录 ctl 和 bulk 进展及各层积压 |
| D3 | 同两段路径，原 E2E / 1 MiB 块、下载 4 MiB、上传单块 ACK 业务列 | 每协议 / 方向先 1 轮 × 30 秒；需归因时扩到每格至少 3 轮 | 分别记录收到的 transport / piece 字节与完整认证块 goodput；不得把未完成块记为已验证业务成功 |
| D4 | Reno / BBR 等候选，同夹具单变量对照 | 仅在 D1–D3 证据支持且有可维护候选后执行 | 先写控制器决策；目前上游依赖没有公开运行时切换选项，不能伪造 bbr 配置。未执行如实记录 |
| D5 | 同物理手机、同服务器、同路线的 WSS / Hysteria / 原生 QUIC | 独立现场门禁 | 本轮 Mac 参考端不代替；生产入口、手机和协商控制器须实际核对 |

D1 单段和 D2/D3 双段的吞吐不可直接相除作 adapter 开销百分比：它们的拥塞域、ACK 路径与数据编码不同。D1 用于发现线路底线，D2/D3 才在相同两段拓扑下比较供给 / 业务成本。若任何准备阶段失败，独立保留，并不算零带宽。

执行前修订：D1 前两轮原始 QUIC 已从约 31.5 降至 2.5 Mbit/s，明显存在时变因素。因此 D2/D3 正式比较放在同一服务、同一轮次内交错执行，统一预热 5 秒 / 计量 20 秒 / 最多 60 秒排空，至少 3 轮；奇数轮原负载先、偶数轮流水线先，协议顺序亦交错。原负载保留 1 MiB / 单块上传；诊断负载为 64 KiB、上下行最多 4 MiB 在途；E2E / piece / Relay 均保留。原定 D3 30 秒预跑改为与 D2 相同的 20 秒以减少比较变量，固定块计量误差仍报告。交错不能消除公网波动，不以此直接证明某个控制器的因果收益。

## 3. 计量与诊断要求

- D1 连续按接收 / 验证字节计数，不等 1 MiB 完整块；数据模式已知且逐段验证，控制报文和传输开销单独计。接收端固定单调时钟窗口，预热 / 排空不混入；上传以服务器接收端窗口为准，不能以客户端 Write 返回当公网交付。
- D2/D3 同时保存底层接收进展、完整认证 payload、应用 ACK 和结束在途量。原完整块 goodput 与新的连续进度保持独立，不将未认证 piece 记为有效文件字节。
- 每轮保存 measurementStarted / measurementComplete、时长、准备耗时、错误阶段、终止原因；断开 / EOF / 取消不能自动判成功。计划轮次全部入结果，分位数保留未回复探针，失败不可隐藏在成功均值里。
- QUIC 连接两端记录 RTT、cwnd、bytes-in-flight、packet / byte loss、PTO 和 stream / connection flow-control 事件；诊断使用 opt-in，缺省不产生文件，不记录凭据 / 业务正文。诊断开销和截断须报告。
- 每秒记录源端提交 / 接收字节、有效字节、队列 / backlog 与控制回复。跨机器使用相对时间，不用未同步的墙钟直接相减成单向延迟。
- 同一阶段使用固定构建、证书 / 主机校验、IPv4 和源路由，记录二进制 / 源码哈希、CPU / RSS、UDP 缓冲与 drops 差值。后台工作与网络不受控因素明确列出。
- bulk 停止供给后明确发送端目标与接收进度。性能窗口结束、取消残余数据与完整排空分别报告；固定预算耗尽仍失败，不以放宽预算宣称提速。

## 4. 资源与执行边界

继续使用独立 worktree `orbis-native-quic`，不改变默认 WS、生产部署、账号 / 配对和 UI。临时公网服务使用真正 Relay `45.58.185.226` 的空闲高端口、独立 TLS 根与隔离身份；防火墙仅允许本次源 IP。运行器持有前台 SSH / 子进程所有权，stdin EOF、取消与有界服务期限都触发清理。不得停用户 Hysteria 或其他容器，不修改全局 sysctl / 网络整形。

本轮不启动模拟器。构建前检查 80% 内存门槛；Go 夹具固定产物目录 `.artifacts/quic-diagnostics/bin/`，串行构建，`GOMAXPROCS=2` / `-p 2`。若使用移动端构建 / 设备，另按共享入口与租约规则执行，不能沿用本次公网所有权冒充设备许可。

结束必须独立回查本任务容器、监听、owner 防火墙规则、远端目录、私密配置和本机子进程；保留 cleanup.json、cleanup-audit.json，并检查共享资源队列。失败写 cleanup-required，不能只凭命令退出码宣称释放。

## 5. 证据与报告

证据根目录 `.artifacts/quic-diagnostics/`；每次运行创建新目录，记录 plan / source / binary hashes、topology、raw.jsonl、每秒 progress / transport metrics、resource / network snapshots、run.log、summary.json、result.json 与清理审计。短跑、正式轮次和失败分别保留，不覆盖旧目录。

汇总同时给出所有尝试数、可确认完整窗口数、错误、有效样本吞吐中位数 / 范围及逐轮表；只有配对条件足够且全部失败公开时讨论差异。报告必须回答：低吞吐最早出现在哪层，观察支持 / 排除了什么，还缺什么证据。控制器、真实手机与受控 Q12 未跑时明确列出，不写“全部验收完成”。

执行记录随测量追加。D0 / D1 / D2 / D3 本轮执行完成，结果见[分层诊断报告](native-quic-layered-results-20261104.md)。D1 接收端 20/20 固定窗口无校验错误；D2/D3 三轮交错共 24/24 窗口校验 / 排空通过，4800/4800 控制探针返回。真实手机、长时 / 受控网络、接收条件和控制器的额外单变量对照仍未执行，不能转记通过。

执行中发现的接收条件另列：D2 / D3 的独立 UDP socket 已出现内核 drops；通过容器入口 PID 的 fd 与 socket inode 核对归属，同时发现 cgroup CPU throttling。后续归因应先对接收缓冲 / CPU 限额做单变量对照，再评估拥塞控制器；本轮不修改运行中的条件、全局 sysctl 或生产配置。当前只读采样不能证明所有波动由其中某项引起。
